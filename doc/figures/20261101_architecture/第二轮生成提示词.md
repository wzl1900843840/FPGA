全图四层。最上方是一条唯一的主图像流水线；中间为缩略图与音频支路；下方为交互控制；底部为时钟条和图例。一个浅灰虚线大边界标“安路 EG4S20BG256 · FPGA硬件逻辑”，TF卡、显示器、PC和板载输入在边界外。不要绘制芯片引脚或电路原理图。

D用稍大分组框：内部“SDRAM控制器↔图像缓存”，下方短注“三路仲裁：图像写入／视频读取／缩略图构建；视频低水位优先”。D代表访问子系统，禁止写乒乓仲裁。读写双向关系仅在D内部控制器与存储之间表示。

中间两条独立支路必须完整：
①D→J“缩略图构建与缓存”→G。J为支路，不串在主像素链里。G内部小字仅列“中文OSD／字幕／参数菜单／缩略图／波形”。

支路线沿独立水平通道走线，不得借用其他线段造成错误合并。

控制层：外部“按键／SW1～SW3”→N“消抖与播放参数控制”；N橙色虚线分别指向F、G和K，表示播放、图层、音量设置。“用户参数Flash”↔N，不得连接到应急状态机。
外部“SW4本地告警”→P“双源告警与应急状态机”；外部PC↔Q“UART接入／事件上报”；Q↔P。P用橙色虚线分别连接F、G、K，标“应急画面／状态／提示音”。P内短注“本地源或串口源有效即告警；ACK仅确认接收；全部来源解除才恢复”。SW4节点与P各出现一次，不拆出第二个重复状态机。
PC小字“演示楼层、查询、事件、人工ACK”，UART链路为青色双向箭头。

## 图2-3

生成一张完整、精确、易读的中文软硬件协同架构图，4K横版16:9，纯白底，扁平工程论文风格，与蓝色FPGA系统图统一；深蓝文字、浅蓝硬件框、浅青软件框、橙色下行命令、蓝色上行事件。无立体阴影、无装饰电路、无界面截图。标题：“图2-3 FPGA硬件逻辑与PC监控上位机软件协同架构图”。所有文字端正清晰、中文无错字，字号够大，模块只出现一次。先规划连线再排版。

左右两大边界：左45%“FPGA硬件终端”；右40%“PC监控上位机｜Python / Tkinter”；中间留15%独立通信通道。顶部架构占75%，下方事件流程占25%。外框不越界，不画云平台或真实电梯控制器。

左边硬件中，靠中间通信通道放两个清晰端口：RX在上、TX在下。下行接收必须完整连接：
UART RX→“控制写帧校验：会话号／序号／CRC16”→“命令解析与分发”。
解析器分支分别到三个清晰框：
“FLOOR：楼层/方向/门演示状态”；
“ALERT / ACK：告警源与事件确认”；
“SUB：字幕更新”。
另外RX分支→“只读查询 BOOT? / RESCUE? / ELEV? / SUB?”，只读查询不需会话写帧封装。
“SW4本地告警源”与“串口ALERT告警源”各自单向接入“告警与事件状态机”；ACK从解析器接入状态机作匹配ID确认。状态机分两条输出：①“画面与提示音控制：PIC1～4日常／PIC5应急／中文状态”；②“事件编号／状态上报／有限重发”。事件上报→“RESCUE CRC封装”→UART TX。只读查询响应也接TX。严禁画成显示模块串行驱动上报模块。

右边软件分层框，底“transport.py｜串口收发”，向上连接“protocol.py｜封装、解析、CRC校验”，再向上连接“core.py｜会话、命令调度、设备与事件状态”，顶层并列“ui.py｜看板、楼层演示、事件时间线、人工ACK”与“journal.py｜日志与历史回放”。相邻软件层使用双向箭头表示收发与状态传递。外部操作者只连接ui.py，“人工确认”由ui.py经core、protocol、transport下发；不要把人直接连journal或UART。小注“PC不参与FPGA图像渲染；SIM/回放仅用于演练”。

中间必须出现两个独立有向通道，不能接错端口：
橙色PC→FPGA：从transport端口出发，连到UART RX；文字“HELLO / FLOOR / ALERT / ACK / SUB / 查询”。
蓝色FPGA→PC：从UART TX出发，连到transport端口；文字“RESCUE+CRC／状态回读／启动里程碑”。
传输标注“UART 115200 bit/s · 8N1”。小注“控制写帧：会话号+序号+负载+CRC16；CRC是完整性校验，不是加密认证”。不要把写帧会话结构错误加到上行RESCUE帧。

底部浅灰流程区：标题“人工接收确认与解除恢复：典型操作顺序”。7个等宽框横向严格依次编号，使用阿拉伯数字1至7，不用可能变形的圈号：
1 告警触发→2 应急提示与事件上报→3 PC校验并展示→4 人工发送匹配ID的ACK→5 FPGA接受并回读ACKED→6 所有有效告警源解除→7 恢复日常显示。
在框5下用橙色短注“ACKED仍保持告警提示”；框6下短注“解除条件独立于是否ACK”。该流程是典型操作顺序，不是解除必须先收到ACK的门禁。
框2下用独立细分支注明“未确认：每次约1秒等待，首次后最多重发2次→TIMEOUT；有效事件匹配迟到ACK仍可接受”。
最底部短注“楼层为演示输入；ACK仅表示接收确认，不表示故障解除或救援到场”。

所有导线正交且避开文字，每条箭头有准确起止节点，未连接的交叉使用跨线桥，不要多余环线、悬空线或边框外的重复UART TX箭头。
