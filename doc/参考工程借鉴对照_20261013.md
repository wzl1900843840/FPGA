## 2. 可直接借鉴的内容

### 2.1 复位同步释放模板

参考文件：`project_code/dependencies/lesson36_build/src/reset_sync.v`  
当前文件：`src/user_source/rtl/reset_sync.v`

参考工程为 `mem_clk`、`pixel_clk`、`pixel_clk_5x` 和 `sys_clk` 各实例化一个“两级触发器、异步断言、同步释放”的 `reset_sync`，并把 PLL `locked` 纳入各域复位条件。当前工程已经采用同样的基本结构，因此不建议复制代码；建议借鉴两点：

1. 将“PLL 未锁定”和“外部复位”统一定义为域复位输入，避免某个域先运行；
2. 对复位扇出大的 FIFO/预取逻辑继续使用本域 ready/释放握手，而不是用普通逻辑门控时钟。

当前工程已有 `media_frame_reader.v` 的 FIFO release 计数和跨域重装逻辑，参考工程没有提供可替代当前版本的更强实现。后续复位优化要以当前 `SWNS=0.325 ns` 的实际构建为基线。

### 2.2 读写突发的“整笔准入”思想

参考文件：`project_code/rtl/memory/media_frame_reader.v`、`project_code/rtl/memory/media_frame_loader.v`  
当前文件：`src/user_source/rtl/media_frame_reader.v`、`src/user_source/rtl/media_frame_loader.v`

参考代码明确区分：

- 一笔突发开始前检查控制器空闲、刷新不活跃、FIFO 保留空间；
- 突发开始后不把 `busy` 当作逐字 ready，避免半笔突发被拆断；
- 像素域用 toggle 请求换图，内存域等待在途数据排空后再重装；
- FIFO 水位、在途字数和下一笔突发长度共同参与准入。

当前工程已经拥有这些核心机制，并且增加了 `MAX_INFLIGHT_BURSTS`、共享 SDRAM 仲裁和更细的 FIFO 就绪保护。真正可借鉴的是参考代码的注释和验证契约：把“控制器 busy/refresh 是整笔突发准入信号，不是每字节 ready”写进接口说明，并把以下场景列为必测：连续切图、刷新撞击、FIFO 接近满、在途返回晚到、短帧和换图请求过快。

### 2.3 错误码分层和跨域快照

参考文件：`project_code/rtl/io/sticky_error_cdc.v`、`project_code/board/player_excellence/src/media_player_excellence_top.v:374-395`  
当前工程：已有存储、视频、配置和音频错误路径，但未完全采用同名模块。

参考实现不是把变化中的多位错误总线直接跨时钟域，而是在源域锁存一次错误码，再用每位两级同步和目标域保护周期原子发布。这个思路值得吸收，尤其适用于：

- mem 域 SD/FAT/BMP/loader 错误到 sys 域 UART/数码管；
- pixel 域 underflow/视频错误到 sys 域报告；
- 音频 HDMI 包/PHY 错误到统一状态显示。

迁移时必须保持“错误码与 valid 一起发布”，不能只复制 `sync_2ff` 到每一位却继续读取变化中的总线。建议先做一个独立 `sticky_error_cdc`，仿真验证后再替换直连路径。

### 2.4 按键事件统一入口

参考文件：`project_code/rtl/io/param_menu_controller.v`、`project_code/board/player_excellence/src/media_player_excellence_top.v:168-238`  
当前文件：`src/user_source/rtl/dual_key_chord_router.v`、`src/user_source/rtl/param_menu_controller.v`

参考工程将短按、长按、组合键保存、参数菜单和 Flash 服务 ready 集中在系统时钟域，再通过事件脉冲进入视频域。当前工程已经基本采用这一设计，而且当前版本的上电音量策略更符合用户要求。

可借鉴的细节：

- 参数菜单只输出 `cfg_update_valid` 单拍，周期/音量新值在同一拍提交；
- 长按和短按在释放时结算，避免按住不放重复触发；
- Flash 未 ready 时禁止保存事件，避免上电阶段丢写请求；
- 菜单事件带 `menu_kind`，UART 可以区分音量和周期变化。

不应复制参考工程的默认音量 64。当前工程的 `cfg_volume` 复位值和 `RESTORE_VOLUME_ON_BOOT=0` 必须继续保持 0。

### 2.5 小 ROM 替代动态字符逻辑

参考文件：`project_code/rtl/display/brand_watermark_24.v`、`project_code/rtl/display/subtitle_scroll_24.v`、`project_code/rtl/display/status_osd_overlay.v`

参考工程把 12×12 汉字行数据放在小 ROM 中，并对 Logo/字幕 stage 同步延迟 RGB、HS、VS、DE 和坐标。当前工程已经有照片 Logo 和更丰富的状态/参数显示，但可以借鉴：

- 固定 Logo/短句的字形数据采用可综合的 `case` 或明确的 ROM 初始化方式；
- 不在每个像素周期重新计算完整字符内容，参数变化时先缓存字符编号；
- 叠加模块输出必须同步延迟整套视频时序，不只延迟 RGB。

参考工程的 `status_osd_overlay.v` 仍使用 `/8`、`%8` 和组合 `font_row`，它是可读性示例，不是当前时序优化的最终实现。当前音轨路径已经是最差路径，不能原样引入更多组合 OSD。

## 4. 不建议借鉴或应保持当前实现的内容

### 4.1 参考工程的音轨可视化过于简单

参考文件：`project_code/rtl/display/promax_audio_waveform.v`。它只有 32 点波形、单线、零轴和峰值柱，使用 `/4` 等组合除法，没有平滑连线、包络、柔光、峰值保持和静音渐隐。

当前文件：`src/user_source/rtl/promax_audio_waveform.v`。当前版本已有 64 点双缓冲、插值连线、75%/87.5% 透明混合、填充包络、网格、峰值保持和静音衰减，功能和观感均更完整。参考音轨模块不应覆盖当前实现；真正可借鉴的只有“帧边界换 bank、采样域与显示域解耦”的基本原则，而当前工程已经实现。

### 4.2 参考工程固定“全部四图完成后才显示”

参考顶层的 `player_enable_mem` 只有在 `image_complete == 4'hf` 时才置 1，README 也要求等待图片加载完成。这个策略会放大上电黑屏时间，与当前用户明确提出的约 5 秒启动问题相冲突。

当前工程的首张有效照片提前显示、其余照片后台加载是正确方向，不应回退。可以借鉴的只有完成位和错误码语义，不能复制“全图完成才开屏”的门槛。

### 4.3 参考工程的配置 CRC 组合函数

参考文件：`project_code/rtl/config/config_journal.v`。它用 `crc16_word` 对 80 bit 数据一次性组合展开；当前工程的 `config_journal.v` 已把 CRC 拆成两次 40 bit 计算，并保留槽位、版本和保存状态。

参考版更短，但组合 CRC 不是低功耗或时序优化方案。当前后续若要优化，应改为顺序 CRC 引擎，在 50 MHz 系统域按字节/片段计算，并逐项验证 Flash 记录格式兼容，不能回退到 80 bit 组合展开。

### 4.4 参考工程的 OSD 组合除法和无流水链

参考 `osd_overlay_24.v` 明确写着纯组合、无延迟；它适合教学演示，但不适合当前已有 0.325 ns 像素裕量的版本。当前工程的状态/参数/字幕已经做了帧边界提交和部分预计算，后续应继续流水化、缓存字符索引和同步时序，不应把参考的组合 OSD 直接替换进来。

### 4.5 参考工程的启动 SPI 分频和固定加载策略

参考 `sd_media_service.v` 使用初始化慢分频、正常传输快分频，这个分层值得保留；但当前工程已经把正常 SD SCLK 提升到 12.5 MHz，并加入首图提前显示。不要仅复制参数或增加等待；应以实板测量 SD 卡响应、FAT 碎片、FIFO 背压和首图时间后再调整。

## 5. 当前工程建议吸收的三项改进

### P0：补齐统一错误快照

新增或整理一个与参考 `sticky_error_cdc` 同等语义的模块，将 mem/pixel/audio 错误码锁存后跨域发布到 UART、OSD 和数码管。验收重点是多位错误码不撕裂、错误只在复位后清除、故障发生后仍能显示细分码。此项不改变图片正常路径，收益主要是可维护性、现场排故和比赛展示可信度。

### P1：为音轨/OSD 引入“区域判定 → 几何/字形 → 颜色”的流水接口

参考工程的 Logo/字幕 stage 已经展示了“RGB 与整套同步信号一起延迟”的接口风格。当前应在 `promax_audio_waveform.v` 和参数 OSD 中沿用这一边界，但不复制参考的简单波形。首轮只拆 1～2 级，逐项综合，目标是改善 0.325 ns 裕量；每增加一级都要检查音频 Data Island 使用的 `video_x` 和 DE 是否仍对应同一像素。

### P1：把按键/菜单/状态报告做成演示契约

参考工程的 UART 报告器可借鉴事件分类：启动 banner、切图、音量/周期变化、亮度变化和首次错误分别排队输出。当前工程已有 UART 和状态显示，建议增加统一事件编码和启动时间戳，而不是增加更多屏幕文字。这样可以直接支撑“5 秒黑屏定位”和答辩的可重复性。

## 6. 建议验证矩阵

| 类别 | 参考工程可借鉴的检查 | 当前工程必须保留/新增的检查 |
| --- | --- | --- |
| 复位 | 每个时钟域独立同步释放，PLL lock 前不放行 | 复位发生在不同相位、FIFO release、首图和 HDMI 重新锁定 |
| SDRAM | 整笔突发准入、在途数据排空、FIFO margin | 共享读写仲裁、首图后台加载、连续切图和刷新撞击 |
| SD | 初始化与数据传输分频、CRC/响应超时 | 12.5 MHz 实板兼容性、不同卡、碎片 FAT、首图时间 |
| OSD | 字形 ROM、RGB/HS/VS/DE/X 同步延迟 | 透明度、Logo 位置、状态/参数/字幕不遮挡照片 |
| 音频 | 图片编号与音频/提示音绑定、错误代码 | 上电静音、波形与真实送出样本一致、音画同步 |
| 错误 | sticky code + valid 原子发布 | UART/OSD/数码管显示相同细分码、故障后可恢复 |
| 资源 | 参考 bit 只作功能基线 | 当前 LUT 81.73%、DSP 58.62%、SWNS 0.325 ns 作为硬约束 |

## 7. 最终建议

当前工程不需要大规模回退或重新拼装参考工程。建议按以下顺序吸收：

1. 先提取参考工程的错误快照和事件报告思想，风险低、比赛展示价值高；
2. 再以当前 `media_frame_reader` 的实现为基础补充复位/突发验证，不替换已有首图和共享 SDRAM 逻辑；
3. 最后在独立分支中做音轨/OSD 一到两级流水，并用最新布局布线报告确认时序收益；
4. 真实 PCM 音画联动作为功能增强，必须在确认默认静音和 SD/音频带宽后再启用；
5. 保持当前 Logo 素材、照片优先透明混合、字幕去署名和缩略图居中，不引入参考工程的“米醋电子工作室忧郁”文字。
