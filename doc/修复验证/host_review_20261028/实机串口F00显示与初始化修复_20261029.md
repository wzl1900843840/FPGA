# 实机串口 F00 显示与初始化修复

日期：2026-10-29。针对 COM18 连接后原始串口持续收到数据、主面板却显示未回读的问题。

## 现场证据与原因

用户截图及 `ui_simulation.jsonl` 中的 COM18 会话记录显示：

```text
ELEV?
ELEV=F00,D=S,DO=M,A=0
INFO?
ERR
```

日志已将该行分类为 `elev`，无效计数为 0，说明收行与正则解析成功。问题位于状态解释和操作门禁：旧 `known` 由 1～5 层演示范围决定，F00 被视为未知，方向/门状态也随之隐藏；开始演示与手动下发又要求已知楼层，形成无法初始化的互相等待。

固件 `top_tf_hdmi_audio.v` 在复位时把楼层清零、门状态清零。`subtitle_uart_controller.v` 将门状态 0 编码为 M，ELEV? 未携带楼层有效位，所以不能把上电 F00 直接宣称为实际位于 0 层。当前板卡对 INFO? 返回 ERR，应继续使用已有 v1 ELEV 命令。

## 修改

1. 状态仓库区分 `status_received`（收到了楼层/方向/门报文）、`known`（有可展示的非占位楼层）和 `demo_floor`（能否定位到 1～5 层井道）。B1、06、99 等合法回读不再被演示范围隐藏。
2. F00 显示“已解析 · 待初始化”和原始 F00 提示；方向显示停止，M 显示未知。旧 ELEV? 不提供故障码时显示“未提供”，不伪造无故障。
3. 收到新鲜状态且合成告警为 0 时，允许用户明确点击“初始化演示”或手动下发；连接本身不自动改变楼层。初始化命令发送后等待 ELEV? 回读，OK 不会被当成已应用楼层。
4. 界面与核心都检查状态时效及告警，过期/未同步/有效告警不开放普通楼层控制。继续演示仍需要能定位到 1～5 层的回读。
5. INFO?/STAT? 不支持或未回应时使用 v1 兼容查询；能力探测超时不再一概把正常演示暂停。普通事务按预期报文类型完成，避免异步回包错误释放事务槽。
6. 未修改 RTL、BIT、引脚、波特率或旧接收端程序。未抢占已被用户窗口打开的 COM18，也未通过外部脚本向板卡发楼层或告警命令。

## 使用

1. 断开并关闭旧窗口，重新双击工程根目录 `start_console.cmd`。
2. 选择 COM18 并连接。上电未初始化时，预期显示“已解析 · 待初始化”，方向停止、门未知。
3. 点击“初始化演示”从 1 层开始，或手动选择楼层后下发。两种操作均需告警无效且状态新鲜。
4. 原始日志预期先有 `ELEV=F01,D=S,DO=C,A=0`、OK，随后 ELEV? 回读实际已应用楼层，主面板再显示对应楼层。后续自动演示每 2 秒更新一次。
5. 若仍持续 F00，保留初始化命令、OK/ERR 和下一次 ELEV? 的完整日志定位设备侧应用情况，不能仅凭发送成功宣称显示成功。
