# 复位与保持修复

## 已修复根因

内存域复位及换帧清空信号经公共 FIFO reset 直接进入像素预取器异步复位，目的域未同步释放，导致 recovery 违例。现在公共清空仍保留；`prefetch_release_pix` 两级同步释放像素预取器，并在复位期间禁止读、有效输出，写端沿用两级就绪隔离。

约束仅覆盖新增目的域复位释放链及厂商 FIFO 内部复位同步链的异步输入。普通像素寄存器、RAM 地址和 FIFO 指针仍进行时序分析；未降低不确定度、未降低时钟频率。

TD 默认 route fix_hold=on 后仍留下约 -0.07ns 的 RAM 地址保持违例；显式执行官方 `fix_hold` 后改善为 +0.026ns，建立裕量保持 +1.203ns（第一次诊断快照）。`tools/repair_routed_hold.tcl` 已接入独立构建流程，报告和 BIT 在修复后一起重新生成。

约束审查另发现像素/串行时钟原来建立在布线输出网上，PLL 原始输出脚未直接有时钟约束。将建钟位置移至 clkc[3]/clkc[4]，频率、主时钟与相位不变，重新完整构建验证。

深度检查还暴露 `USR-6135`：CLKC0_EXT 反馈专用 BUFG 没有普通寄存器时钟负载，check_timing 报告反馈补偿经过本地网络。原始引脚建钟、对反馈源网/输出网强制专用布线、显式标记 clock net 均未消除警告；这些诊断结果均未发布。

复用已有像素全局时钟作为 CLKC3_EXT 反馈后，完整实现仍报告USR-6135，故该试验未发布。

依据本机原厂《PLL用户指南》TN305第3页4b诊断内部反馈后，TD6.2在bitgen明确拒绝CLKC0_INT（RUN-8419），该方案未发布。

当前采用TD6.2原语模板的受支持默认VCO_PHASE_0反馈，保留NORMAL模式。反馈分频改40、输入分频仍2，VCO为50/2×40=1000MHz。C0—C4输出分频、粗细相位及模拟环路参数保持原值，移除反馈专用BUFG并将未使用fbclk输入接0。40/40/25/125MHz和10ns SDRAM相移通过厂商模型断言复核。系统/内存/像素边界仍沿用原有CDC握手，不新增跨域豁免。此项必须经新copy快照完整构建、时钟检查和回归后才可作为可靠版本；实板锁定与显示仍单独待验收。
