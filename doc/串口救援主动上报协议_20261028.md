# 梯安·灵眸应急联动终端：串口救援主动上报

日期：2026-10-28。RTL 仿真、物理实现和实板验收分别记录，不能互相替代。

## 1. 触发与发送格式

沿用板载 UART：115200、8N1、无流控、ASCII、CRLF 结尾。

- 串口输入 ALERT=ON，或合法 ELEV=...,A=1，设置串口告警。
- SW2=0、SW3=1 进入电梯演示后，SW4=1 设置本地告警。0/1 为 FPGA 输入逻辑电平。
- 有效告警 = 串口告警 OR 本地告警。有效告警的上升沿主动发送 A=1；下降沿主动发送 A=0。
- 来源重叠时，清除其中一个不会产生虚假的恢复消息。持续告警、重复 ON 和重复 A=1 不持续刷屏。
- 每个变化事件发送一帧，不依赖查询，也不等待 HDMI/PIC5/媒体状态机正常。

示例（每行带 CRLF，固定 43 字节）：

    RESCUE,ID=0001,A=1,F=05,D=U,DO=C,S=U,E=00
    RESCUE,ID=0002,A=0,F=05,D=U,DO=C,S=U,E=00

| 字段 | 定义 |
|---|---|
| RESCUE | 主动救援事件标识 |
| ID | 16 位十六进制事件序号，复位后从 0001 开始，每次边沿加一，FFFF 后回卷；不是持久化全局编号 |
| A | 1=请求救援，0=告警已清除；清除不表示救援人员已处置完成 |
| F | 00～99 或 B1～B9；未收到有效楼层帧时为 -- |
| D | U=上行、D=下行、S=停止；来自最近一次有效输入 |
| DO | O=开门、C=关门、M=未知 |
| S | U=UART，L=本地开关，B=两者；恢复消息保存解除前最后一个有效来源组合 |
| E | 捕获时的 8 位十六进制系统故障码；00=当时无系统故障 |

命令继续返回 OK 或既有错误回执。主动消息可能在 OK 前或后，上位机按完整行解析。

## 2. 实现与边界

实现位于 src/user_source/rtl/uart_status_reporter.v，顶层复用现有单个 UART TX，不新增输出引脚。

1. 50 MHz 系统域捕获有效告警边沿，锁存事件编号和状态快照。
2. 四项队列保存待发事件，另有一个正在发送的快照。现场数据变化不改写已捕获报文。
3. 完整行之间优先调度救援事件；已开始的状态行或命令回执先发完，避免交错。
4. 43×10/115200≈3.73 ms 是单帧理想线速时间，不含字节握手、已有报文和排队；不是实板测量值。
5. 队满拒收新事件，序号仍前进，置粘滞标志，使顶层系统故障码变为 87，直到复位。既有 ERR 状态行仍沿用从无错到有错时报告的规则；已存在其他故障时不保证另发 ERR 87。队列不能替代输入去抖。
6. 媒体故障不阻止系统域发送；断电、系统时钟/复位或 UART 物理链路损坏仍会阻止上报。

本版完成“事件主动发出”，尚无外部接收确认、CRC、超时重发、接收端去重、跨复位保存或联网能力。串口完成发送不等于救援平台已收到，更不等于救援已到场。后续 ACK 应明确请求编号、重发上限、断链状态与接收端职责。

## 3. 演示步骤

    ELEV=F05,D=S,DO=C,A=0
    ALERT=ON
    ALERT=OFF

逐条发送并等待回执；串口助手追加 CR、LF 或 CRLF。预期看到正常回执、A=1 主动消息及 A=0 恢复消息；持续告警不重复上报。再测试 SW4 和双来源重叠。

随后发送 A=0 楼层帧会清除串口告警；SW4 仍为 1 时不会解除合成告警。ELEV? 当前查询解析器保存的楼层帧，不是合成告警真值，不能确认本地开关告警或独立 ALERT 命令的最终状态。
