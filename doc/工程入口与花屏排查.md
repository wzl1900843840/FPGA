## 本轮唯一硬件逻辑修正：SDRAM 周期刷新

`include/global_def.v` 原宏未给除法表达式加括号：

```verilog
`define SDR_CLK_PERIOD 1000000000/40000000
`define SELF_REFRESH_INTERVAL 64000000/`SDR_CLK_PERIOD/2**(`ROW_WIDTH)
```

第二个宏展开成连续整数除法，计算结果为 0。原厂 `sdr_init_ref.enc.v` 的公开逻辑中，计数器一直停在 0，而刷新请求比较值为 `SELF_REFRESH_INTERVAL-10`，因此不会产生周期性自动刷新请求。四图常驻内存依赖刷新保持内容；这与 OSD 正常但图片损坏的现象相符，但不能仅凭此认定花屏已在实物上解决。

修复只涉及两个宏及说明注释：周期表达式加括号；刷新阈值按从 0 开始的计数器减 1。40 MHz 下每 1250 拍（31.25 μs）请求一次刷新，2048 行对应 64 ms。

`tools/test_sdram_refresh.py` 直接提取原厂文件保护段之前的公开计数/请求逻辑进行测试，没有解密或改写受保护代码。修复前复现 `requests=0 interval=0`；修复后验证连续 8 次请求，间隔均为 1250 拍。日志见 `tests/results/sdram_refresh/`。该测试验证刷新请求产生，不模拟受保护的 SDRAM 命令执行及电气时序。

修复前下载产物保存在 `archive/releases/release_before_refresh_fix`。新版本完成构建后，以 `release/manifest.json` 的时间、散列和时序为准；原 `lab_ex4_tf_Fcard_fix.bit` 是旧版本，不用于本轮比较。

本轮已用原 `.al` 完成 TD 综合/布局布线：SWNS +1.182 ns，HWNS +0.017 ns，STNS/HTNS 为 0；14 项已有自检及刷新专项测试通过。下载文件 SHA256 为 `2f70f1343da89d75ea5ee5bd0f29ae10f46837adac80233ecf2771bf526fda3c`。`release` 中只保留这一份活动 `.bit`，旧别名已移入修复前备份。历史完整链路仿真不覆盖原厂受保护 SDRAM 控制器，本轮没有将它重新运行或冒充实板证据。

## 实板复测

使用本轮 `release/lab_ex4_tf_complete.bit`，TF 卡内容保持不变。分别查看四张图片、复位重载、静置超过一分钟再切换，观察花屏是否消失。记录左上图片/模式/错误码与 D 详细码。尚未收到本轮实板结果时，状态只能是“刷新缺陷已修复，花屏待实板复测”，不能写成全链路验收通过。
