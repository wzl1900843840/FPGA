# 梯安·灵眸应急联动终端：国赛收尾审查与优化方案

日期：2026-10-28。工程：D:/FPGA/anlu/example_code111/lab_ex4_tf。器件：EG4S20BG256。

目标：围绕电梯轿厢“日常信息展示—紧急提示—主动救援上报—状态恢复”完成作品收尾。建议以稳定性、可靠性与可复核数据形成竞争力；奖项由评审决定，本方案不把目标当成已取得结果。

## 1. 当前判断与工作边界

项目的优势是单 FPGA 独立实现存储管理、缩放、缓存、视频、音频、OSD 和控制，且能把电梯状态输入与紧急页面关联起来。当前最值得投入的是异常路径和证据闭环，而不是继续扩充特效。

本次已经实现：

1. 合成告警上升沿主动 UART 救援上报，下降沿主动恢复上报；含事件编号、楼层、方向、门状态、来源与故障码。
2. 四项待发队列和独立发送快照；与既有命令回执以整行为单位仲裁；持续告警不重复刷屏；队满置粘滞错误 87。
3. 修复 u_view_sys 同步器的目的时钟：原来仍使用 pixel_clk，输出却被 50 MHz 参数逻辑使用；改为系统时钟及其同步复位。
4. 电梯状态跨域默认值由 16'hc001 改为 16'h4000，消除上电“告警=1、楼层有效=1”的虚假初始快照。
5. 增加串口端到端与事件队列仿真，保留已有 UART 行为；修正 FAT32 测试中 resource_valid 的 4/5 位宽不一致。

本次没有把 ACK/重发、媒体故障下的告警优先显示、提示音联动和电源休眠标成已实现；具体后续项列在第 5～8 节。实板电流、首图时间、冷启动重复性和最终显示稳定性仍需测量。

## 3. 架构与现有瓶颈

### 3.1 数据链与时钟

    TF/SPI → FAT32 → BMP24/2×2缩小 → 写 CDC → SDRAM
                                                   ↓
    HDMI ← TMDS/音频包 ← 波形 ← OSD ← 转场/色彩 ← 帧预取

    UART RX/拨码 → 系统域告警请求 ┬→ 帧提交 → 电梯状态/页面
                                └→ 事件快照/FIFO → UART TX

四个主要时钟域：系统 50 MHz、SDRAM 40 MHz、像素 25 MHz、TMDS 串行 125 MHz，另有 SDRAM 移相采样输出。主动上报不经过显示帧提交，因此显示出错时仍有机会向外报告，但系统时钟/电源故障会同时使它失效。

### 3.3 逻辑复杂度与执行效率

- 像素路径：OSD 字形、阴影、多层选择与波形插值/混色串联。已存在文字与波形之间的整束寄存、波形输出寄存、数值变化才转换 BCD 等优化，不应重复“重新实现”。余下优化需按新 STA 的真实路径选点。
- 文件路径：SD 使用 CMD17 单扇区读取；每扇区有命令、响应、token、CRC 与字节请求等待。FAT32 簇链读取会增加控制开销，8 扇区/簇已在制卡工具中引入，但真实卡兼容和启动收益还未量化。
- 地址运算：FAT 的 cluster×sectors_per_cluster、顶层周期 ms×25000、部分楼层 /10 和 %10 仍存在。常数除法不一定综合成通用除法器，应先看综合结果；不能只按 Verilog 运算符数量判断面积。
- 内存：5 个全尺寸页加 1 个缩略图页共 1,843,200 个 32 位字，约 7.37 MB，接近 8 MiB 容量。静态图片仍逐帧读 SDRAM，约 60 Hz 时理论像素数据约 73.7 MB/s，静态画面不等于内存可停机。
- 启动策略：编译期 ELEVATOR_DEMO_MODE=1 会先读 PIC5；运行时 SW3 进入电梯模式不会改变编译期加载顺序。先读紧急页与优先点亮日常首图存在直接取舍，应分开定义两个指标。

### 3.4 功耗瓶颈

- 默认音量为零只保证输出静音；音频采样节拍、未选中合成器排空、测试音相位、波形模块仍可能持续运行，不能据此声称已实现音频休眠。
- 顶层波形 enable 和数码管 enable 都为常开。数码管扫描、菜单页计时与部分全速计数器在无人交互时仍活动。
- 视频消隐期/面板外，坐标驱动的组合网络仍可能翻转；仅输出 RGB=0 或在末端选择原像素不保证前级逻辑不切换。
- 装载完成后 FAT/BMP 客户逻辑具备自然空闲态，但公共时钟树、SDRAM 刷新及视频读链仍在工作。时钟使能主要压低寄存器与相关数据通路活动，不等同于断电，不能去除器件静态功耗。

功耗方法参考 AMD 官方 UG907 的 Global Clock Enables 与 Methodology for Power and Temperature Measurement：使用真实使能活动率、温度稳定后的对比测量。它是通用方法参考，不代表 EG4S20 具备 AMD 器件的专用原语或电源控制能力。

参考版本 UG907 2026.1（2026-06-23），以及 Intel/Altera Quartus 设计建议 Use Gated Clocks。官方参考地址以便复核：

    https://docs.amd.com/r/en-US/ug907-vivado-power-analysis-optimization/Global-Clock-Enables
    https://docs.amd.com/r/en-US/ug907-vivado-power-analysis-optimization/Methodology-for-Power-and-Temperature-Measurement

## 4. 本次救援发送的设计与边界

    RESCUE,ID=0001,A=1,F=05,D=U,DO=C,S=U,E=00

43 字节含 CRLF；115200/8N1 时理想线速约 3.73 ms。每个有效告警边沿捕获完整快照；来源 U/L/B；无楼层数据时 F=--。相同持续告警不重复发送，解除发送 A=0；事件队列深度 4，加一个在途快照。

新消息在当前完整报文结束后优先发送，不中断回执。四项队列可覆盖日常操作突发，但不是无限缓冲；输入抖动或恶意高速翻转会使队列溢出并显示 87。事件编号在复位后重置，不能作为跨重启全局唯一编号。

这补齐的是“主动请求上报”，尚未确认外部接收成功。ACK、重试、设备标识与外部接收演示建议作为下一阶段可靠通信增强。详细协议见同目录的《串口救援主动上报协议_20261028.md》。

## 7. 低功耗方案与时钟/电源边界

策略按“持续可显示、持续可接收求救”的约束设计。HDMI 维持有效时序，系统域 UART/事件捕获保持唤醒能力，SDRAM 保持合法刷新。

| 措施 | 具体改法 | 预期收益 | 难度 | 代价与限制 |
|---|---|---|---|---|
| 静音时冻结未选音源 | 无音频需求时冻结合成器/测试音相位和数据寄存，保持音频包/必要样本节拍契约，恢复用短斜坡 | 降低无用音源和增益数据路径切换 | 中 | 停止读取 TF 音频会涉及环形缓冲和恢复位置；避免爆音/背压死锁 |
| 波形按需采集与计算 | 普通静音界面可关采集、峰值更新及几何计算；告警安抚页可隐藏波形 | 降低寄存器/组合网络活动并减少遮挡 | 低～中 | 当前已有约六帧视觉衰减，关闭前先让其收敛；保留竞赛可视化演示模式 |
| 面板外/消隐期操作数隔离 | 给代价较大的混色、查表、波形插值输入加稳定保持；同步 valid 与延迟 | 降低不产生可见输出时的内部翻转 | 中 | 多路选择器也占 LUT，需以 VCD/后仿或实测确认净收益 |
| 静态 UI 事件更新 | 数值变化才算 BCD；滚动字幕可选暂停；菜单计时走共享低速 CE | 减少慢控制逻辑全速计数和重复转换 | 低～中 | 保留动画流畅度；现有部分 OSD 已采用事件驱动，不重复改写 |
| 数码管超时熄灭 | 无人操作后 disable 扫描/输出，按键唤醒；告警保留必要提示 | 可能降低数码管驱动电流与扫描翻转 | 低 | 要冻结内部计时/扫描，不只是把段码置空；不能遮蔽关键错误 |
| 资源加载后保持 SD 引脚空闲 | 无 PCM 任务时禁止空转 SPI，请求/返回保持合法空闲 | 减少外设链活动；现有空闲协议需先确认是否已经满足 | 低 | 不能在正在读块或 CRC 检查时停；若已无时钟则没有额外收益 |
| 全局时钟管理 | 第一阶段只用寄存器 CE；确需关域时使用 EG4S20 官方支持的无毛刺时钟资源并验证恢复 | 有机会降低部分时钟网络功耗 | 高 | 不以普通逻辑 clk & enable 造时钟；多域 FIFO、PLL 锁定和复位要重新设计，最终阶段不推荐 |
| 外设电源管理 | 先核对原理图有无独立供电使能；以后版本再考虑负载开关/受控电源域 | 可降低可关断外设静态功耗 | 高 | 当前未确认有可控电源域，不能靠 RTL 凭空断电；不建议改核心电压或频率 |
| SDRAM 自刷新/停显示 | 只有明确进入“允许息屏”模式才研究，唤醒先恢复刷新/读链/HDMI | 深空闲可能降低内存及显示链活动 | 高 | 当前连续显示仍读 SDRAM，不能直接停时钟；息屏会改变产品要求，不列收尾必做 |

数字亮度调整改变像素值，不直接控制外接显示器背光；不能把暗画面当整机节能证据。低功耗对照至少分“FPGA 开发板供电”和“显示器供电”两个测量边界。

## 8. 收尾顺序、验收与停止扩展条件

### 阶段 A：锁定可回滚版本（本次）

- 已建立修改前 Git 标签与外部源码 ZIP；本次功能、协议和计划单独提交。
- 保留历史已知可用发布目录；新构建使用 build_out 的独立副本。
- 全量 RTL 回归、综合与物理报告绑定源码 SHA；负时序结果只保留为诊断，不覆盖正式发布。

### 阶段 B：先消除阻断交付的 P0

顺序：目的域/复位问题 → setup/hold/recovery 全闭合 → 故障+告警显示 → 忙/晚到 PIC5 重试 → 缩略图/菜单应急接管。

每项都先有可复现失败场景，再局部改动并回归；不同时改加载协议、存储布局与视频管线。若改动使已稳定路径退化，保留证据并回退，不能用功能数量掩盖稳定性下降。

### 阶段 C：选做高收益增强

优先级：状态查询一致性与去抖 → 上位机接收演示/ACK → 告警提示音 → 两项可测的 CE/静音省电。只有在稳定发布候选已锁定后才做面积/吞吐实验。

### 阶段 D：建立国赛展示证据

以下是建议验收项与目标，不是已完成成绩：

| 维度 | 方法 | 通过条件/记录内容 |
|---|---|---|
| 时序与资源 | 同一提交跑 TD 全物理实现 | SWNS/HWNS≥0、TNS=0，review recovery/removal 与未约束路径；记录 LUT/REG/BRAM/DSP |
| 冷启动 | 固定 TF 内容与显示器，重复至少 30 次 | 分别记录第一 HDMI 图案、首张有效 TF 图、紧急资源 ready；p50/p95/max，零随机卡死 |
| 救援上报 | 外部接收端记录 TX 报文，逻辑分析仪测请求与 TX | 正常/无图/媒体故障、UART 忙、双来源重叠均正确；无队列积压且普通回执占用下建议整行完成≤10 ms，另测排队上限 |
| 画面告警 | 扫描请求落在帧内不同位置，验证 PIC5/备用页 | 建议重构后可见告警≤2 帧，恢复≤3 帧；现有多级链不先承诺该值 |
| 抖动/队满 | 输入短脉冲与连续边沿 | 正常输入不重复，队满明确 87；不出现残缺报文或无提示丢事件 |
| 异常矩阵 | 无卡、坏 BMP、缺 PIC5、CRC/FAT 错误、读忙 | 告警提示仍可见，发送路径可工作；不能以“拔卡立即检测”代替实际检测机制 |
| 音画联动 | 有音量、静音、背景音/提示音切换 | HDMI 连续、波形对应实际 PCM、无明显爆音，音频声明与实物一致 |
| 功耗 | 同电压、卡、显示内容、音量与温度条件；热稳定后各模式测量 | 分别记录平均/峰值电压电流、功率和测量误差；不得虚报统一百分比 |
| 长稳 | 先 30 分钟冒烟，再 8 小时；时间允许做 24/72 小时 | 记录重启、欠载、错误、温升与上报计数；没有跑完的时间写“未测” |
| 交付复现 | 在独立构建目录按说明生成 | 源码、工具版本、约束、素材、镜像、BIT、SHA256 与验收表一致 |

“UART 已发送”“外部已确认”“救援已受理”三个状态必须区分。PC 接收演示若还没有实现 ACK，只能显示“接收到请求”，不能显示已派单或已到场。

## 9. 四分钟现场叙事

1. 上电：显示启动提示、首图与加载时间，说明全 FPGA 数据链；外部 PC 不参与图像解码或控制算法。
2. 日常：切换安全须知/楼层/社区信息；简短展示缩放、字幕、转场、参数和真实音频波形。
3. 联动：UART 更新楼层、方向与门状态；触发 SW4 或 ALERT=ON，显示紧急页；外部串口接收端出现带楼层的 RESCUE 消息。
4. 异常：在缺 PIC5 或媒体故障条件下再次触发；只有第 6 节 P0 修复验收后才能把备用显示作可靠性成果演示。
5. 恢复与证据：解除两种告警来源，显示恢复消息与普通页面；展示同版本 STA、资源、响应时间及实测功耗表。

讲解主线：“并行显示与独立救援上报、可解释的状态控制、异常下的持续提示”。不宣称控制电梯安全回路，不声称自动识别困人，不把串口上报描述为已经接通公共救援电话。
