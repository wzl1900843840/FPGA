# 应急预警终端场景调研与演示方案

调研日期：2026-10-25  
工程：`lab_ex4_tf`

## 1. 结论

“应急预警终端”有明确的现实需求，但当前 FPGA 工程应定位为：

> **基于安路 FPGA 的 HDMI 应急信息发布与视觉告警节点**

它适合放在校园保卫处、园区值守室、乡镇应急管理办公室、实验室或工业门卫室，负责把预置的应急图片、短字幕、状态信息和提示音稳定显示出来。

当前工程是 640×480 HDMI 原型，不能直接包装成户外大面积 LED 控制器。公开采购中的大屏通常还包含 LED 模组、接收卡、视频控制器、配电、钢结构和安装服务；这些属于后续产品化的显示终端层。比赛现场应展示 FPGA 负责的内容播放、帧缓存、低延迟显示、音画联动和故障恢复。

## 3. 三个可落地的子场景

### 3.1 校园保卫处应急预警终端

**使用地点**：校园保卫处、门卫室、综合楼值守室或应急指挥中心。  
**使用者**：保卫人员、值班教师、实验室管理员。  
**真实需求**：出现火灾演练、人员疏散、实验室危险操作或校园活动变更时，需要在本地屏幕快速显示预置指令，即使上游网络或电脑暂时不可用，也要保持可见。

**当前工程演示方式**：

- TF 卡预置“正常校园展示”和“应急疏散”两组 BMP；
- 通过 K2/K3 或 UART 模拟值班人员选择应急页面；
- 状态区显示 `NORMAL`、`ALERT`、图号、加载状态和错误码；
- 音量保持上电静音，按 K4 后才允许提示音进入；
- 波形用于显示提示音是否正在输出，不能替代消防联动系统。

**建议做深的三项扩展**：

1. 应急优先图层：应急页面暂停自动轮播，使用红/黄状态边框和短字幕；
2. 音画联动：提示音、波形、状态颜色同时变化，突出听觉和视觉双通道；
3. 可靠性显示：首图优先、坏图跳过、错误码和细分码持续可见。

这是最推荐的子场景，因为海南师范大学的公开采购可以直接作为现实需求来源，且与当前按键、OSD、波形和 HDMI 输出链路吻合。

### 3.2 乡镇/园区应急信息发布节点

**使用地点**：乡镇应急管理办公室、园区服务中心、社区值守室。  
**使用者**：应急管理人员、物业值班人员、园区运营人员。  
**真实需求**：日常显示安全宣传、天气防灾和园区通知，发生事件时切换到预置警示页；设备需要长期运行，出现坏图、存储异常或重启时不能无提示黑屏。

**当前工程演示方式**：

- PIC1～PIC4 分别作为日常宣传页、天气提示页、疏散页和设备状态页；
- 自动轮播模拟日常模式，手动切图模拟应急插播；
- OSD 显示当前模式、图片编号、周期、源图尺寸和加载状态；
- 用错误码演示“坏图跳过、保留完整 bank、重新按 K1 初始化”。

**建议做深的三项扩展**：

1. 预置内容分级：常态页、提醒页、告警页使用不同颜色和轮播策略；
2. 帧边界切换：告警页只在帧边界发布，避免半帧和撕裂；
3. 故障可解释：OSD、数码管和 UART 输出同一主错误码/细分码。

天全县项目的公开结果可以作为这一场景的采购依据，但不要声称当前板卡能够直接替代 32 平方米 LED 屏的接收卡和配电系统。

### 3.3 工业门卫/值守室安全提示终端

**使用地点**：工业园区门卫室、生产车间入口、仓储值守室、危险作业培训室。  
**使用者**：安保人员、班组长、设备维护人员。  
**真实需求**：现场需要持续显示安全提示、作业流程、危险区域图片或培训内容，并且要有视频/音频输入和较长质保周期。

**当前工程演示方式**：

- 四张照片替换为“佩戴防护用品、危险区域、疏散路线、设备状态”素材；
- 字幕显示短安全提示；
- 亮度/对比度调节模拟不同厂房照明；
- 音频波形显示安全提示音或测试音的变化。

**建议做深的两项扩展**：

1. 亮度/对比度 + 参数 OSD：针对厂房强光、弱光和夜班环境；
2. 字幕 + 转场：安全指令清晰叠加，切换时避免突兀闪烁。

贵州金西工贸的采购公告明确提出 LED 屏、视频/音频接入、安装调试和 3 年质保，这可以支撑“工业安全显示节点”的现实背景；当前工程仍应定位为 HDMI 原型和演示节点。

### 3.4 社区或道路应急预警信息发布终端

**使用地点**：社区出入口、应急避难场所、道路施工点、桥隧入口、积水路段、交通管制点。  
**使用者**：社区工作人员、道路养护人员、交警或现场值守人员。  
**真实需求**：现场需要快速显示“避险、绕行、封闭、集合、恢复通行”等行动指令。终端不一定要自己判断地震等级或计算气象数据，告警内容可以由上游平台、值班人员或运营人员制作后写入 TF 卡或通过通信接口下发。

**当前工程可直接采用的素材组织方式**：

| TF 卡图片 | 预置页面 | 可对应的实际场景 |
| --- | --- | --- |
| `PIC1.BMP` | 正常状态/安全提示 | 社区日常宣传、道路正常通行 |
| `PIC2.BMP` | 地震演练/避险提示 | 社区地震演练、应急避难场所指引 |
| `PIC3.BMP` | 道路封闭/施工绕行 | 道路施工、桥隧检修、交通管制 |
| `PIC4.BMP` | 暴雨积水/人员疏散 | 内涝提醒、临时封控、集合点提示 |

因此，**不需要 FPGA 自己确定“地震几级”**。页面只需要表达告警类型、行动指令、更新时间和发布状态；如果上游已经给出震级或预警等级，可以由运营人员制作到图片中，或通过 UART 下发短文本。演示时应明确标注“预置内容/模拟告警”，避免被误解为地震监测设备。

**建议做深的三项扩展**：

1. **告警优先级与页面状态**：告警页暂停自动轮播，在帧边界生效；恢复指令到达后回到正常模式。
2. **行动指令图层**：字幕显示“请沿箭头撤离”“前方封闭，请绕行”“前往 A 避难点”，状态区显示 `ALERT`、页面编号和发布状态。
3. **视觉与声音双通道**：提示音或测试音通过波形显示；维持上电静音，音量由现场人员主动开启，避免设备复位时突然播音。

社区和道路可以共用同一套 FPGA 播放核心，只更换图片、字幕和部署外壳。道路户外版本还需要高亮度屏、防水、防尘、UPS、通信链路和远程维护，这些属于产品化配套，当前竞赛工程不宣称已经具备。

## 4. 当前工程需要补充的最小功能

如果确定采用“校园/园区应急预警终端”，不建议立即重做整套架构，只需增加一层低风险的应急策略：

1. 在系统控制域增加 `normal / alert / recovery` 三态；
2. 增加一组 `alert_request` 事件，来源可以是按键组合或 UART 命令；
3. 在帧边界提交 `alert_active`、`alert_page` 和 `alert_text`；
4. 应急状态下暂停自动轮播，优先显示预置应急 BMP；
5. 状态 OSD 显示 `ALERT` 和细分状态，恢复时回到原图号和原轮播模式；
6. 保持上电音量为 0，提示音必须由操作员主动升音量，避免应急演示破坏既有启动静音要求。

这组功能可以复用现有帧边界提交、字幕、音频波形、错误码和双缓冲逻辑，不需要大型 FFT、网络处理器或复杂缩放。

## 5. 现场演示脚本

1. **正常状态**：上电，音量为 0，先显示正常宣传图，状态区显示 `NORMAL`。
2. **模拟告警**：按键或 UART 发送告警事件，下一帧切换到预置应急图，状态区显示 `ALERT`。
3. **视觉提示**：字幕显示“请保持通道畅通”或“实验室暂停进入”，波形区域显示提示音活动。
4. **故障演示**：选择坏图或模拟加载错误，显示错误码，保持上一张完整图，不进入无提示黑屏。
5. **恢复运行**：清除告警，恢复自动轮播，展示周期、图号和模式的帧边界恢复。

## 6. 答辩时必须说明的边界

- 当前板卡没有接入火灾、温度、烟雾、GPS、气象或园区平台实时数据；演示事件由按键/UART 模拟，内容由 TF 卡预置。
- 当前输出为 640×480 HDMI 原型，不能称为户外大屏接收卡或完整 LED 控制系统。
- 当前音频可视化是时域波形，不是完整 FFT 频谱。
- 当前默认音频为 FPGA 合成音调，PCM/WAV 播放需要单独启用并完成实板验证。
- 低功耗应表述为默认静音、减少空闲翻转和后台加载策略，不能在没有电流测试前给出百分比。

## 7. 多场景包装方式

建议采用一个产品名称，下面挂多个部署场景：

> **应急信息发布与视觉告警终端**

| 部署变体 | TF 卡内容 | 现场动作 |
| --- | --- | --- |
| 社区地震演练 | 避险图、集合点、楼栋疏散图 | 值班人员选择演练页 |
| 道路施工/封闭 | 绕行图、封闭提示、恢复通行页 | 养护人员切换告警页 |
| 暴雨积水 | 积水路段、禁行、避险路线 | 预置页或 UART 更新文字 |
| 校园/园区安全 | 疏散指令、实验室禁入、集合点 | 按键模拟应急插播 |
| 工业门卫/值守室 | PPE 提示、危险区域、作业暂停 | 显示安全状态和提示音 |

比赛答辩时只选择一个主场景，例如“社区地震应急信息发布”；其余作为同一终端的素材变体，说明“更换 TF 卡即可适配”。这样既体现多个实际落地场景，又不会把作品讲成多个互不相关的系统。

## 8. 推荐最终包装名称

比赛现场建议使用：

> **Anlogic FPGA 应急信息发布与视觉告警终端**

一句话介绍：

> 面向社区、校园、道路和园区值守点的离线应急信息发布节点，在无额外处理器的 FPGA 内完成预置图片、字幕、HDMI 音视频、波形可视化和故障状态显示；上游内容由 TF 卡或 UART 更新，演示中用按键模拟告警触发。

这个说法既有公开采购需求支撑，也与当前工程真实能力一致。
