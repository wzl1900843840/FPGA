# 第0课 产品包装——从"打通基础拓展链路"到"打动评委的需求化场景产品"

> **本课解决赛题的哪点**：赛题简介第一句的应用场景定位 + 赛题简介第二句的FPGA价值主张（"更确定的时序、更低的显示延迟、更高的可靠性"）+ 注意事项"最终设计应该具有实用性"。前面16课把基础和扩展功能都做出来了，本课教你怎么给每个功能找到"非做不可"的理由
>
> **先学什么**：第8课（OSD字幕）、第9课（转场）、第11课（音频可视化）、第12课（缩放）、第13课（亮度对比度）——五个扩展的技术实现；

## 一、为什么场景比你想的重要

赛题里藏了四个信号：

1. **赛题简介第一句就是场景清单**——"适用于数字广告牌、商业展陈终端、应急信息发布、车载辅助显示及教育演示等应用场景"。注意这五个场景的共同点：全是**把预置内容稳定播放出去**的场合，没有一个需要实时数据接入——出题人在场景清单里就把系统边界划好了。
2. **赛题简介第二句是价值主张**——"相比依赖通用处理器的软件栈方案，FPGA方案能够以更确定的时序、更低的显示延迟和更高的可靠性完成音视频展示"。你的场景必须能回答"为什么用FPGA不用树莓派"，答案就在这句话里。
3. **注意事项明确"最终设计应该具有实用性"**——写进赛题注意事项的话，就是评分关注点。
4. **扩展要求说"建议选择1-2项做深做透，完成即可获得额外区分度"**——做深的前提，是场景里有足够的动机支撑。

最常见的四种翻车：

- **两张皮**：文档前两页场景写得热闹，后面的功能与场景再无呼应；
- **功能清单式答辩**："我们实现了字幕、转场、缩放……"评委追问"为什么需要"，答不上来；
- **为炫技而扩展**：频谱可视化做了，但场景里没有人需要"看到声音"；
- **信息系统幻觉**（本课重点防）：把媒体播放器讲成叫号机、路况屏、温控看板——这类场景的核心卖点是实时数据，而 HX4S20C 上根本没有数据来源，叙事与实现两张皮，答辩必被戳穿。

## 二、把赛题翻译成"能力原子"，并守住板卡边界

不要背赛题原文，把每条要求翻译成可复用的能力：

| 赛题要求 | 能力原子 | 技术本质 | 对应课程 |
|---|---|---|---|
| 基础1 | 从移动存储读取媒体内容 | SPI + FAT32 + BMP解析 | 第1、6课 |
| 基础2 | 周期性内容展示 + 人工干预 | 播放控制状态机 | 第2课 |
| 基础3 | 音画并行、时间对齐（对象=板上自产音频） | I2S + ACR/N/CTS | 第3课 |
| 基础4 | 无主机独立运行 | Flash固化 + 上电自启 | 第5课 |
| 扩展1（字幕） | 动态文字与静态画面合成（文字来自OSD字库ROM，预置或经UART下发） | Alpha混合 + 字库 + 滚动 | 第8课 |
| 扩展2（转场） | 帧级无缝切换 | 双缓冲/帧边界提交 | 第9课 |
| 扩展3（缩放） | 任意输入分辨率适配 | 几何变换（最近邻→双线性） | 第12课 |
| 扩展4（调节） | 画质参数实时可调可显示 | 流水线参数化 + OSD回显 | 第13课 |
| 扩展5（频谱） | 板上音频转视觉呈现（赛题原文："先验证48kHz测试音稳定输出，再从24-bit PCM样本计算频谱能量"） | PCM→频谱能量→渲染 | 第11课 |

**板卡边界审查（本课第一铁律）**：场景里出现的每一种信息，来源只允许以下四种——第五种"外部实时数据"在板上不存在：

| 合法来源 | 说明 | 典型用途 |
|---|---|---|
| TF卡预置内容 | BMP图片（工程增强可含WAV音频） | 轮播素材、字幕文字预置 |
| 板上时钟驱动的时序行为 | 50MHz有源时钟衍生的定时 | 轮播间隔、滚动速度、倒计时 |
| 板上输入 | 4按键 + 空闲拨码（SW3/SW4） + UART配置 | 模式切换、参数调节、演示触发 |
| FPGA自产内容 | OSD字库、测试音、转场、缩放、频谱渲染 | 字幕、告警音、可视化 |

需要"实时叫号数据、温度、路况、检票信息"的场景不是不能写——必须改写成**内容运营模式**：实际部署中内容由运营方制作（换卡或上位机经UART/网口下发），本系统只负责**确定性播放**。这才是播放器的定位，也是赛题说的"实用性"。

**核心认知**：场景不是功能的"装饰"，而是能力的需求来源。写文档时箭头方向是"场景需求 → 能力"，不是"我做了能力 → 硬找个场景安上"。

## 三、场景设计第一法则：功能动机链

每个功能必须能回答四问：

1. **谁在用？**——写不出具体人群，说明场景太虚；
2. **这个功能删掉会怎样？**——答不出后果，说明动机不成立；
3. **评委拨动拨码那一刻，场景故事还在吗？**——答不出，说明演示与场景脱节；
4. **这个信息的来源在板上吗？**——不在四种合法来源之内，说明场景越界，必须改写成内容运营模式。

五个扩展各自对应一类"需求原型"：

| 扩展 | 需求原型 | 动机模板（可直接套用） |
|---|---|---|
| 字幕 | 信息叠加（板上时钟或内容运营） | "通知/指引文字随TF卡内容更新，滚动叠加不遮挡画面"（倒计时类由板上时钟实时驱动） |
| 转场 | 观看体验 | "该场景观众会长时间注视，硬切闪烁会造成XX问题" |
| 缩放 | 内容异构 | "内容来自多个来源，分辨率无法统一" |
| 调节 | 环境挑战 | "部署环境光照会变（昼夜/室内外），固定画质不可读" |
| 频谱 | 声音可感知（对象=板上音频） | "环境嘈杂/用户听障/场所静音，板上告警音/测试音必须被'看见'" |

**反例与正例**：

- 反例："我们实现了音频可视化功能，将频谱叠加到画面上。"
- 正例："应急插播时板上告警音持续鸣响，嘈杂现场或听障人员可能听不到。我们对这路24-bit PCM实时计算频谱能量并叠加到画面——声音信息变成视觉信息，这是无障碍设计，不是特效。"

## 四、场景发生器：五维组合法

单个灵感不可复制，组合方法可以。五个维度：

| 维度 | 决定什么 | 示例值 |
|---|---|---|
| A 载体 | 部署形态、观看距离、是否无人值守 | 站台/柜台/客厅/车间/驾驶舱……（20+） |
| B 主题 | 内容是什么、哪来的、分辨率统一吗 | 广告/相册/规程/菜单/科普/展品……（15+） |
| C 功能 | 扩展组合：5选1有5种、5选2有10种 | 字+频 / 效+缩 / 调+字……（15种） |
| D 环境挑战 | 扩展4与基础4的动机 | 强光/夜间/粉尘/潮湿/狭小/无人值守 |
| E 板上音频角色 | 基础3与扩展5的动机（音源=测试音/WAV，板上自产） | 提示音/告警音/背景乐/节拍音 |

**组合数：A(20) × B(15) × C(15) = 4500 种方向**，D和E是修饰项。

组合示范（每次组合完立刻过四问检验——特别是第4问板卡边界，不合格就换）：

- "社区 × 应急科普 × 字+频 × 昼夜 × 告警音" → 社区应急信息发布屏：常态轮播安全宣教图（预置内容），紧急模式按键触发插播＋告警音频谱满屏（板上音频），夜间自动低亮度（调）
- "客厅 × 相册 × 效+频 × 昼夜 × 背景乐" → 数字相框：翻页转场＋背景乐（TF卡WAV）频谱律动
- "车间 × 工艺 × 字+缩 × 粉尘 × 提示音" → 实训工艺看板：工序字幕常驻＋多来源图纸缩放适配

## 五、四个完整案例

### 5.1 案例A：应急信息发布终端（官方钦定场景，五扩展全活且全板内可实现）

**场景叙事**（技术方案可直接用的写法）：

> 社区/园区的应急信息屏。常态时段轮播安全宣教图与公益内容（TF卡预置）；紧急情况下按键一键切换到应急页——疏散路线图全屏插播、应急指令滚动字幕、板上告警音持续鸣响并频谱化满屏显示；部署环境昼夜光照差异大，亮度对比度需现场可调并OSD回显；宣教素材来自多部门、分辨率不一；应急终端7×24无人值守，断电重启即恢复播放。

**完整功能映射表**：

| 赛题要求 | 场景需求 | 系统实现 | 演示动作 |
|---|---|---|---|
| 基础1 | 宣教图+应急页双素材组 | TF卡FAT32，常态/应急两组BMP | 上电自动搜索播放 |
| 基础2 | 常态轮播+人工切换 | 按键手动切 / 自动轮播 | 按KEY切换宣教图 |
| 基础3 | 告警音与画面同步 | 板上变频测试音→HDMI | 紧急模式音画同步 |
| 基础4 | 断电重启即恢复 | Flash固化，上电自启 | 现场断电再上电 |
| 扩1字幕 | 应急指令滚动显示 | OSD字库+Alpha混合+滚动（文字预置） | 紧急模式字幕滚动 |
| 扩2转场 | 常态体验+紧急插播分级 | 常态淡入淡出；**紧急页硬切+闪烁边框** | 按KEY触发紧急插播 |
| 扩3缩放 | 多部门宣教素材分辨率不一 | 最近邻起步，评估双线性 | 播放320×240小图自动适配 |
| 扩4调节 | 昼夜光照差异 | 空闲拨码调亮度，OSD回显参数 | 拨SW3，OSD显示当前值 |
| 扩5频谱 | 告警音必须被"看见" | 板上24-bit PCM→频谱能量→满屏叠加 | 紧急模式频谱随告警音跳动 |

这张表最有讲头的一行是扩2的"转场分级"：常态内容用淡入淡出，紧急插播**不用转场直接硬切+闪烁边框**——"我们知道什么时候不该用转场"，这一句就是答辩亮点。

**硬件资源分配**（对齐官方框图：KEY2/KEY4消抖、数码管状态显示、拨码含官方占用位）：

| 板上资源 | 分配 | 场景语义 |
|---|---|---|
| KEY2 | 紧急插播/解除 | 一键进入/退出应急模式 |
| KEY4 | 常态手动切图 | 宣教内容翻看 |
| 其余按键 | 轮播启停 / 演示复位 | 定时开关 / 答辩重来一遍 |
| SW3（空闲拨码） | 亮度档位 | 昼夜适配，OSD回显 |
| SW4（空闲拨码） | 高对比模式 | 烟雾/强光环境可读 |
| SW1（官方占用） | 蜂鸣器开关 | 板载原生功能，告警听觉冗余 |
| SW2（官方占用） | 数码管/双色LED切换 | 官方原生功能 |
| 数码管 | 状态机显示 | 空闲/搜索BMP/写入SDRAM/OSD叠加（官方框图原文） |
| 双色LED | 常态绿 / 应急红 | 模式一眼可辨 |
| 蜂鸣器 | 与告警音同步 | 听觉冗余 |

（答辩演示脚本模板）：

| 时间 | 操作 | 画面/声音 | 讲解词要点 |
|---|---|---|---|
| 0-10s | 断电再上电 | 直接进入轮播 | "固化运行，断电重启即恢复——应急终端的可靠性底线" |
| 10-20s | 按KEY4 | 切换宣教图 | "手动切换与自动轮播" |
| 20-40s | 按KEY2 | **硬切应急页+字幕滚动+告警音+频谱满屏** | "紧急信息即时到达，不用转场；告警音频谱化——听障人员也能看到" |
| 40-55s | 拨SW3 | 亮度渐变+OSD显示参数 | "昼夜环境适配，参数在帧边界生效防跳变" |
| 55-70s | 再按KEY2回常态 | 淡入淡出转场 | "常态内容的观看体验——转场分级使用" |
| 70-85s | 播小图 | 320×240自动放大 | "多部门素材分辨率异构" |
| 85-90s | 收尾 | 回到轮播 | "一个固件整合全部功能" |

**FPGA价值主张落地**（赛题原文三优势的场景化翻译）：

- 更确定的时序 → 应急插播在帧边界原子生效，无撕裂无跳变；
- 更低的显示延迟 → 按下按键到应急页出现，延迟以帧为单位；
- 更高的可靠性 → 无操作系统、无软件栈死机，上电即播，看门狗异常自恢复。

### 5.2 案例B：客厅音乐画屏（做深两项示范）

主打扩2+扩5，教"少即是多"：赛题说选1-2项做深——这个场景示范怎么**砍**功能：字幕只留曲名一行，调节只留昼夜三档。

**音源边界先说清**：赛题要求的是48kHz测试音，扩展5的原文路径是"从24-bit PCM样本计算频谱能量"——本课程工程已扩展WAV播放（第10课），所以画屏的音源是**TF卡WAV文件**，频谱分析对象是这路板上PCM。答辩被问"音乐哪来的"，答"TF卡WAV，板上I2S输出流"——完全站得住。

"做深"的含义：
- 频谱做指数平滑（移动平均），条形不闪烁抖动；
- 转场与音乐节拍对齐（帧级提交，淡入淡出时长配合乐曲速度）；
- 每个参数都讲得出取值理由。

做深 = 参数细节与体验打磨，不是功能数量。

### 5.3 案例C：产线工艺看板（内容运营模式+可靠性叙事示范）

主打扩1+扩4。先把越界风险拆掉：产线的"实时工单/产量数据"不进本系统——由产线管理系统生成图片/文字，经上位机下发到TF卡（或运营换卡），本系统是**工艺内容的确定性播放终端**。板上呈现的是：工序SOP轮播、当前工序字幕（预置文字+按键翻页）、多来源图纸缩放适配、车间昼夜高对比模式。

卖点不是功能而是FPGA本身（赛题原文三优势）：
- 无操作系统，不存在软件栈死机、重启、系统更新；
- 显示时序由硬件确定，不存在掉帧卡顿；
- 看门狗 + 错误恢复FSM，保证异常自动恢复；
- 车间粉尘 + 昼夜班光照差异 → 高对比模式的动机；
- 工序提示音（板上音频）→ 音频同步输出的动机。

这条路线适合不擅长讲故事的技术型选手：把"为什么不用树莓派/安卓盒子做"讲透，同样成立。

### 5.4 越界改写示范：医院分诊叫号屏怎么"救回来"

学员最容易想到的场景就是它，也最容易写越界。改写三步：

1. **拆掉实时数据**：叫号序列来自医院HIS系统——本系统不碰。改写成"宣教内容轮播终端"：科室介绍、医生排班、健康宣教图轮播（预置内容），叫号文字与号码由HIS经上位机定期生成图片/经UART更新字幕缓存。演示时用按键模拟一次叫号插播，并在文档里明说"演示用按键模拟，部署时由上位机下发"。
2. **保留合法动机**：诊区昼夜光差（调节）、宣教图多科室分辨率不一（缩放）、安静场合不宜跳变（转场）、提示音可视化服务听障患者（频谱，对象=板上提示音）、无人值守上电即播（固化+可靠性）。
3. **话术换锚点**：不说"我们做了叫号系统"，说"我们做了医院宣教与信息发布的确定性播放终端"——播放器定位，一个字都不多承诺。

这三步是通用手术：任何越界场景都能这么救——**数据归属上游，播放归你**。

## 六、工程约束反过来塑造场景设计

四个赛题硬约束，每个都影响场景设计：

1. **"不能多次加载镜像分别实现基础和扩展"** → 场景必须设计成"一个系统里的多个工作模式"。做法：一个按键循环切换模式（常态/应急/调光演示），全部集成在一个固件里。场景叙事里写"单系统多模式"，不要写"多套演示"。
2. **"固化上电即运行，无需PC"** → 场景叙事天然要求无人值守（应急终端/站牌/产线都成立）；消费类场景要补一句"无需电脑主机"。答辩现场务必演示断电再上电。
3. **"评测不依据资源大小，推荐优化逻辑和最低功耗"** → 文档不要拿资源占用当卖点；讲带宽预算（SDRAM读写带宽 vs 视频+频谱叠加的像素流量）反而加分。
4. **板上资源按官方口径分配**（赛题解析slide 8/18-20）→ 4组拨码中官方已占用1组蜂鸣器开关+1组数码管/双色LED切换开关，用户实际可用的空闲拨码约2个（与按键配合做亮度/对比度档位足够）；官方扩展框图用KEY2/KEY4并配数码管状态显示（空闲/搜索BMP/写入SDRAM/OSD叠加，以及分辨率、缩放比、亮度、对比度、频谱模式）——场景卡的交互设计照这个口径写，答辩现场与官方例程风格一致。另外赛题解析提醒：板卡虽有千兆网口与72组扩展IO，"扩展越多，时钟、带宽、缓存和系统稳定性的验证压力也越大"——没有万全验证就不要把外设写进核心叙事。

## 七、落到文档与答辩

**应用场景章节结构**（四段式）：

1. 总场景叙事（150字以内，案例A那种写法）；
2. 功能映射表（5.1那种九行表）；
3. 平台化底座论证（升维，见下）；
4. 拓展场景列举（8-10个，一句一个，从附录严选清单的12例中挑）。

**平台化底座论证**（示范段落，可直接改写）：

> 本设计的媒体播放底座与应用场景解耦：图像链路对内容透明（任意BMP均可轮播），OSD引擎对文本透明（滚动字幕可承载通知、指引、警报等任意预置文字），音频可视化对板上音源透明（任意48kHz PCM流均可分析），参数调节对部署环境透明（可适配强光至夜间场景）。应急发布、展陈导览、产线看板等场景无需修改RTL，仅通过TF卡内容与运行参数即可适配——场景是"内容+参数"的配置，而非另一套硬件。

**答辩话术公式**：场景痛点 → 该功能如何消解痛点 → 现场演示动作，三句一组，念完就拨开关。永远不要说"我们做了X"，说"场景里有人需要X"。

**FPGA三优势话术**（每个场景至少备一条，赛题原文直译）：

- "更确定的时序"→ 所有切换与参数在帧边界原子生效，无撕裂；
- "更低的显示延迟"→ 按键到画面以帧为单位响应；
- "更高的可靠性"→ 无OS死机，上电即播，看门狗自恢复。

## 八、常见翻车点

1. **两张皮** → 用映射表自查，表里填不满的行就是两张皮的地方；
2. **信息系统幻觉** → 每条信息过"来源四问"：叫号、温度、路况、检票这些数据在板上没有来源；改写成内容运营模式或按键模拟，文档里明说；
3. **为全覆盖而全覆盖** → 文档叙事可以全覆盖，实现深做两项，并在文档里明说；
4. **多套镜像演示** → 违反赛题注意事项，用模式切换设计规避；
5. **场景太玄** → 评委要能在脑子里"看见这块屏挂在哪"，写不出部署位置的场景都是虚的；
6. **演示依赖PC** → 现场拔电再上电，这10秒比任何话术都有说服力；
7. **频谱对象说不清** → 被问"可视化的是哪路音频"必须秒答"板上24-bit PCM（测试音/WAV）"。
