# 第11课 音频波形可视化

> **本节课解决赛题哪点**：拓展要求——音频可视化功能。在屏幕上实时显示音频波形和峰值条，让你的媒体播放器看起来更专业、更有科技感。

## 一、官方例程的音频可视化现状与局限

### 1.1 官方例程有什么

官方例程**没有音频可视化功能**。官方例程的音频部分只有ROM固定音调输出到HDMI，屏幕上不会显示任何与音频相关的视觉效果。

这意味着：你能听到声音，但屏幕上看不到声音的"样子"。一个专业的媒体播放器，比如Winamp、Foobar2000、手机上的音乐APP，都会有频谱显示、波形显示、音量条等音频可视化效果。没有这些，播放器就显得很"裸"。

3. 波形+峰值条的视觉效果已经足够专业，能满足拓展要求
4. 实现简单，代码量小（promax_audio_waveform.v只有约140行）

这又是一个工程思维：**够用就好，不要过度设计**。拓展要求只说"音频可视化"，没说必须是FFT频谱。波形+峰值条已经能达到很好的视觉效果，实现又简单，何乐而不为？

## 二、音频可视化的核心概念

### 2.1 时域波形 vs 频域频谱

在讲实现之前，我们先搞清楚两个基本概念：时域和频域。

**时域波形**：就是我们平时看到的声音波形，横轴是时间，纵轴是振幅（音量大小）。比如你说话的波形，就是声音随时间变化的曲线。时域波形直接反映了声音的"形状"，实现简单，只需要把音频样本按顺序画出来就行。

**频域频谱**：是通过傅里叶变换把时域信号转换成频域信号，横轴是频率，纵轴是该频率的能量。比如一段音乐，低频是鼓点，中频是人声，高频是镲片，频谱图就能看到这些频率分量的能量分布。频域频谱效果更炫，但实现复杂，需要FFT算法。

完赛工程做的是**时域波形**，不是频域频谱。大家一定要区分清楚，不要以为音频可视化就一定是FFT频谱。

### 2.2 抽取（Decimation）

音频采样率是48kHz，就是每秒48000个样本。而显示帧率是60fps，就是每秒60帧。如果每帧显示48000/60=800个样本，那波形会非常密集，看不清楚。

所以需要**抽取**：每隔N个样本取1个，降低样本率，让波形看起来更舒服。

完赛工程的抽取参数是`DECIMATE=12`，就是每12个样本取1个。每帧取多少个样本呢？`SAMPLE_COUNT=32`，就是每帧显示32个样本点。

我们算一下：32个样本 × 12抽取 = 384个原始样本。每帧60fps，384×60=23040样本/秒，约是48kHz的一半。也就是说，波形显示的是约半秒的音频数据，这个长度看起来比较舒服，不会太快也不会太慢。

用一个decimate_count计数器，从11减到0，减到0的时候存一个样本，然后重置为11。这样每12个样本就取1个

### 2.3 双缓冲（Ping-Pong Buffer）

音频可视化有一个经典问题：**写和读的冲突**。

写侧在不断地采集音频样本，写到缓冲里；读侧（显示）在不断地从缓冲里读样本，画到屏幕上。如果写和读同时访问同一个缓冲，可能会出现"撕裂"——这一帧显示的波形，一半是旧数据，一半是新数据，看起来在跳。

[代码/图示块另行核对]

有两个缓冲：bank0和bank1。写侧往write_bank指向的缓冲写，读侧从display_bank指向的缓冲读。write_bank和display_bank总是指向不同的缓冲，所以写和读不会冲突。

每帧开始时（frame_start，就是vsync下降沿），如果写侧已经采集够了32个样本，就交换write_bank和display_bank。这样，读侧这一帧显示的是上一帧写好的完整数据，不会撕裂。

这是一个非常经典的设计，在图形显示、视频处理中广泛使用。

### 2.4 峰值检测

除了波形，完赛工程还显示一个**峰值条**，就是显示当前音频的最大振幅。

峰值检测很简单：在采集样本的过程中，记录这32个样本中绝对值最大的那个，作为这一帧的峰值。显示的时候，在波形旁边画一个竖条，高度和峰值成正比。

峰值条的作用是什么？让用户直观地看到当前音量有多大，有没有爆音（峰值接近最大值就是音量过大）。专业的音频设备都有峰值表（VU表），我们这个就是简化版的VU表。

读这段抓三个要点：

**frame_start时交换的条件**：`capture_count == SAMPLE_COUNT`（32）才交换。如果这一帧还没采够32个样本（比如音频流刚启动），就不交换，display_bank保持上一帧的数据，避免显示半帧新数据。交换时display_peak也跟着切：write_bank=1就取peak_bank1。

**抽取怎么实现的**：decimate_count从11减到0，减到0时存一个样本，然后重新装DECIMATE-1=11。这样每12个pcm_tap_valid脉冲才存一个样本到bank里。存的是高8位pcm_tap_left[15:8]——16位有符号样本取高8位，范围-128~127，正好对应波形高度64像素（居中±32）。

**峰值清零的时机**：frame_start时，如果write_bank=1，就清peak_bank0（因为下一帧要写bank0）；如果write_bank=0，就清peak_bank1。这样当前正在写的bank峰值不清，下一个要写的bank先清零。注意display_peak在交换时锁存，不在采集时实时变——显示的是上一帧完整的峰值。

**显示侧逻辑**：

显示侧是组合逻辑（always @*），根据当前像素坐标计算输出颜色：

1. **区域判断**：当前像素是否在波形区域内（WAVE_X ≤ pixel_x < WAVE_X+WAVE_WIDTH，WAVE_Y ≤ line_y < WAVE_Y+WAVE_HEIGHT）
2. **轴线判断**：line_y == CENTER_Y（波形区域垂直中心），画中心轴线（深灰色）
3. **样本索引计算**：sample_index = (pixel_x - WAVE_X) / SAMPLE_SPACING，其中SAMPLE_SPACING = WAVE_WIDTH / SAMPLE_COUNT = 512/32 = 16。就是每个样本点占16个像素宽度。
4. **波形像素判断**：从display_bank读取样本值，sample_y = CENTER_Y - sample_value/4（样本值越大，波形越靠上）。如果line_y在sample_y±1范围内，就是波形像素（绿色）。
5. **峰值条判断**：在波形区域右边（WAVE_X+WAVE_WIDTH+8到+16），如果line_y在峰值高度范围内，就是峰值条像素（橙色）。
6. **颜色输出**：波形像素→绿色(24'h20ff90)，峰值条→橙色(24'hffb020)，轴线→深灰(24'h406060)，其他→原视频像素(rgb_in)。

关键讲三个细节：

**sample_y = CENTER_Y - sample_value/4**：sample_value是8位有符号（-128~127）。除以4是因为波形高度64像素，中心在WAVE_Y+32=432，最大振幅127/4≈32像素，正好填满高度。sample_value为正（波形正半周）时sample_y=432-正数，位置靠上；为负时sample_y=432-负数=432+|负数|，位置靠下。

**wave_pixel为什么±1？** sample_y算出来是整数，但波形线只有1个像素宽太细了，±1就是3像素高的线，肉眼看得清。这是工程上常见的做法——波形线适当加粗。

**peak_height = display_peak >> 2**：display_peak是0~127的绝对值，右移2位（除以4）变成0~31。峰值条从波形底部往上画peak_height像素。>>2和波形的/4用同一个缩放因子，保持比例一致。

**关键设计决策**：
1. **同时钟域设计**：采集和显示都在像素时钟域，避免跨时钟域同步的复杂性。PCM样本通过valid脉冲输入，在像素时钟域采集。
2. **双缓冲避免撕裂**：write_bank和display_bank分离，frame_start时交换，确保显示的是完整的一帧数据。
3. **抽取降低数据率**：每12个样本取1个，每帧32个样本，波形看起来舒服，不会太密集。
4. **像素级叠加**：和OSD叠加原理一样，判断像素坐标替换颜色，实现简单，资源占用少。
5. **波形+峰值条组合**：波形显示时域形状，峰值条显示音量大小，两者组合视觉效果好，实现又简单。

## 六、常见问题与调试技巧

### Q1：波形不显示

**排查步骤**：
1. 检查enable是否为1
2. 检查pcm_tap_valid是否有脉冲（用ILA抓）
3. 检查pcm_tap_left是否有数据（不是全0）
4. 检查波形区域参数是否正确（WAVE_X/Y/WIDTH/HEIGHT是否在屏幕范围内）
5. 检查display_valid是否为1（采集够32个样本后才会显示）

### Q2：波形闪烁/撕裂

**可能原因**：
1. 双缓冲交换逻辑有问题，write_bank和display_bank指向同一个缓冲
2. frame_start检测错误，不是vsync下降沿
3. 采集速率太快，一帧还没显示完就交换了缓冲

**解决方法**：
1. 检查write_bank和display_bank的初始值（应该相反）
2. 检查frame_start = vs_q && !vsync（vsync下降沿）
3. 确认只有capture_count==32时才交换

### Q3：波形太密集/太稀疏

**可能原因**：
1. DECIMATE参数不合适。太大→太稀疏，太小→太密集
2. SAMPLE_COUNT参数不合适。太大→太密集，太小→太稀疏

**解决方法**：

1. 调整DECIMATE（默认12，可试8/16/24）
2. 调整SAMPLE_COUNT（默认32，可试16/64）
3. 原则：每帧显示的原始样本数 = SAMPLE_COUNT × DECIMATE，约2000-5000比较合适

### Q4：峰值条不动/一直满

**可能原因**：
1. 峰值检测逻辑错误，sample_abs计算不对
2. 峰值没有在帧开始时清零
3. 音频数据本身就是静音（全0）或满幅（±32767）

**解决方法**：
1. 检查sample_abs的补码转绝对值逻辑
2. 检查frame_start时peak_bank是否清零
3. 用ILA抓pcm_tap_left，确认音频数据有变化
