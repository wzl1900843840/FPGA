## 3. 工程入口与文件组织问题

### 3.1 为什么会有两个工程

早期整合时额外创建了 `lab_ex4_tf_complete.al`。核对后，它与原 `lab_ex5_i2s_v1.0.al` 的源文件集合和器件配置相同，没有必要同时存在。

处理方式：保留原入口，重复入口移到 `doc/project_entry_archive/`，以 `.bak` 等非活动扩展名保存。不要在 TD 中再次保存已经归档的旧 complete 工程窗口，以免重新生成第二个 `.al`。

### 3.2 哪些文件实际参与编译

以活动 `.al` 中的文件清单为准，不能根据目录里是否有同名文件判断。当前正式引用的读 FIFO 是：

```text
src/user_source/rtl/afifo_32_16_256.v
```

原工程 IP 对照文件是：

```text
src/user_source/hdl_source/IP/afifo_32_16_256.v
```

最终没有切换工程入口，也没有新增另一个 FIFO 模块；直接恢复正式引用文件的内容。文件名虽然包含 `32_16_256`，实际模块是 `rfifo_32_32_512`，读侧实例按 32 位、512 深度配置，应以模块与参数为准。

整合阶段确实在 `rtl` 目录引入过教程模块，不能把整个历史工程描述成“只修改了原有几个文件”。但本次最后的 FIFO 实验没有重新设计架构，只恢复官方 IP 并保留现有连接。

## 5. SDRAM 与时钟方面保留的修正

### 5.1 刷新周期整数宏

原 `SDR_CLK_PERIOD` 的除法表达式缺少括号，嵌入 `SELF_REFRESH_INTERVAL` 后变成连续整数除法，导致计算结果为 0，未产生预期的周期刷新请求。

修正括号和计数起点后，40 MHz 下每 1250 拍发出一次请求，即 31.25 μs；2048 行对应 64 ms。`tools/test_sdram_refresh.py` 验证了连续请求及间隔。

**状态：刷新请求逻辑缺陷已在专项测试中修正，但这一修改没有单独消除实板花屏。**

### 5.2 数据对齐、突发与刷新应答

使用原厂加密控制器及 IS42s32200 行为模型后，发现并处理了：

- SDRAM 返回数据与有效信号的拍数关系：在 `hdl_source/SD/sdram.v` 包装边界增加数据寄存对齐。
- 新突发与控制器忙／刷新窗口相撞：reader、缩略图构建器和写 CDC 在突发开始处进行判断；已开始的突发保持连续。
- 刷新应答持续两拍：在 `sdr_init_ref.enc.v` 的公开逻辑中检测应答边沿，避免一次应答产生相邻刷新命令。

这些修正在模型测试中有对应证据。厂商文件的受保护数据块没有被解密或改写。

### 5.3 相位约束

厂商 PLL 模型测得：mem 时钟周期 25 ns，pixel 周期 40 ns，serial 周期 8 ns；移相输出相对 mem 晚 10 ns。SDC 相位据此从 172.8° 修正为 144°，硬件 PLL 配置不变。

**边界：模型通过只验证模型条件下的时序与功能，不证明芯片、板卡和显示器上的完整链路已通过。**

## 6. 最关键的实板定位过程

### 6.1 一级：像素域本地图案

路径：

```text
像素域本地图案 → 现有 HDMI 编码 → 串行输出 → 显示器
```

图案包括八色条、灰阶、彩色渐变和黑白棋盘格，不只显示全黑、全白等简单颜色。诊断图直接进入 HDMI 桥，旁路颜色调节、转场及所有叠加层。

隔离措施包括禁止 TF 文件加载启动、禁止 SDRAM 应用读写请求、忽略真实 SDRAM 返回并停止 reader 消费。SDRAM 初始化／刷新仍可运行，但不提供图案数据。

用户反馈：“测试图全部清晰”。这证明该次本地图案经当前输出链路能正常显示，尚未验证 FIFO 和真实存储数据。

### 6.2 二级：合成图案通过现有读 FIFO

路径：

```text
40 MHz 域合成相同图案
  → 现有跨时钟读 FIFO
  → fifo_prefetch_2
  → 像素域数据对齐
  → 与一级相同的 HDMI 输出链路
```

合成模式禁止真实 SDRAM 突发请求、真实返回处理及返回计数；图案位置仅随实际 FIFO 写入前进。仿真强制注入 `valid=1、data=deadbeef`，确认不会混入图案或影响 issued／returned／inflight 计数。

两个模式均逐像素核对完整一帧，共 307200 个像素。它们在 RTL 仿真中通过，但用户随后实板确认：

| 同一固件模式 | 实板结果 |
| --- | --- |
| SW3=0，一级本地图案 | 清晰 |
| SW3=1，二级经 FIFO 图案 | 花屏，无其他叠加图案 |

这一步使排查范围从整个 TF/SDRAM/HDMI 工程缩小到 FIFO、预取、跨域和像素对齐段。此时继续盲改 BMP 或 SDRAM 没有直接证据支持。

### 6.3 恢复官方原始读 FIFO

文件比较发现，改造版相对原版增加了 9 个写地址恒等 LUT：

```verilog
AL_MAP_LUT1 #(.INIT(2'h2)) u_wr_addr_delay (
    .o(wr_addr_ram[wr_addr_bit]),
    .a(wr_addr[wr_addr_bit])
);
```

RAM 写地址也从 `.addra(wr_addr)` 改成 `.addra(wr_addr_ram)`。这些是此前为物理时序加入的延迟单元；RTL 仿真中是恒等映射，所以像素仿真通过并不能证明真实物理实现没有问题。

最终恢复 `.addra(wr_addr)` 及完整原始文件。恢复后的文件与以下三份来源逐字节一致：

1. 当前工程 `hdl_source/IP/afifo_32_16_256.v`。
2. `D:\FPGA\anlu\guanfang\lab_ex4_tf\src\user_source\hdl_source\IP\afifo_32_16_256.v`。
3. 教程“第二讲／第1课_官方例程／IP”下的同名文件。

依据见 [FIFO 来源校验](../tests/results/original_fifo_compare.json)。

## 7. 恢复原始 FIFO 后的时序问题

第一次采用默认优化强度构建时：SWNS 为 −0.289 ns，STNS 为 −3.470 ns，保持检查通过。

失败路径不是写地址保持时间，而是 `mem_clk` 域复位释放到 `pixel_clk` 域预取寄存器异步复位端的 **recovery 检查**。因此不能简单说“换回官方 FIFO，编译通过就可以下载”。

没有放宽 SDC，也没有同时修改预取复位逻辑。改用以下物理优化参数后重新构建：

```tcl
set phyWildParams {place effort high place opt_timing high route effort high}
```

最终 SWNS +0.018 ns、HWNS +0.004 ns、STNS/HTNS 均为 0。保留原有硬宏位置调整和移相时钟本地布线警告，不能称为“零警告构建”。

**结论必须带上物理策略变化：** 原始 FIFO 加上本轮布局布线结果在实板上有效；尚未通过严格的等物理实现比较证明那 9 个 LUT 是唯一根因。当前余量较小，也不能外推为不同构建、温度或长期运行均稳定。

复现命令，在工程根目录运行：

```powershell
D:/Anaconda/python.exe tools/run_local_pattern_test.py --fifo
D:/Anaconda/python.exe tools/build_gui.py
```

保留 `Runs/phy_1/settings.cfg` 的 high 设置。TD GUI 若重新生成默认物理设置，应核对优化强度并重新检查最终时序，不能直接引用旧报告。当前 `.al` 没有因为此次实验而新增第二入口。

## 8. 当前诊断操作与退出方法

烧录本文第 1 节的已验证固件，SW1/SW2 置 0：

| 操作 | 模式 |
| --- | --- |
| SW4=1、SW3=0，按住 K4，按下并释放 K1，再保持 K4 约一秒后松开 | 一级本地图案 |
| SW4=1、SW3=1，重复相同按键操作 | 二级经 FIFO 图案 |
| 松开 K4，拨码全部置 0，再按 K1 | 正常播放器，重新加载照片 |

模式在复位后锁存，运行中只拨 SW3 不会切换诊断模式。诊断不需要 TF 卡。原图案没有 MediaPlayer 字幕、状态 OSD 或波形。

一度生成过 15:43:46 的强制进入中间版本，但在用户补充有效 A/B 结果后已撤回。**当前源码不含该临时 `DIAG_FORCE_FIFO` 参数，不要照历史阶段说明重新加入。**

## 9. 这次排查得到的经验

- **文字清晰不代表图片链路正确。** OSD 在存储读出之后叠加，可能掩盖前级数据已经损坏的事实。
- **切图编号变化不代表照片正确。** 控制路径和像素路径必须分别验证。
- **仿真通过不代表实板通过。** 本次二级 RTL 图案逐像素正确，实板却花屏，是最直接的反例。
- **诊断旁路需要自证。** 禁止请求、忽略返回、正确计数及正式工程引用，缺一项都可能产生错误结论。
- **优先恢复有实板依据的官方基础 IP。** 对 FIFO、复位、时钟等底层模块做物理优化时，要保存原版并安排可复现的 A/B 对照。
- **明确区分 RTL 变化与物理实现变化。** 本轮还提高了布局布线优化强度，不能把成功全部归于单个 RTL 差异。
- **用时间、散列和输入快照区分固件。** 文件名相同不代表内容相同，路径不同也不代表源工程不同。
- **保留已通过版本，避免继续叠加猜测性修改。** 新实验以失败边界为依据，一轮完成后再决定下一轮。
