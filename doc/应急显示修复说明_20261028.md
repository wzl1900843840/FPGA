# 第3关：应急显示完整性

## 实现

- 告警优先于媒体故障；有效日常页不因另一文件损坏而停播。故障码保留在OSD。
- 播放器将告警作为电平请求，忙时等待、PIC5晚到后自动提交；像素域在帧边界优先处理应急，解除时拒绝迟到PIC5。
- 像素域保存实际可见日常页，解除时直接恢复；保存页无效则选择首个有效日常页，无有效页则保留故障页等待。
- 告警单独双触发器跨域，避免等待楼层多位状态提交；停止普通转场，禁用普通切图、菜单和缩略图覆盖。
- 保存缩略图视图/焦点及自动模式；告警期间屏蔽模式配置更新。
- SW4双沿稳定20ms后更新，本地来源与UART来源逻辑或；进入菜单不清除仍有效的本地开关告警。
- 缩略图改用第5号存储bank，随帧请求锁存地址，不再以实时跨域视图偏移修改在途突发。第4号仍是PIC5。

## 同时发现并修复的既有验证问题

`14374ae`独立源码副本可复现本地图案测试首像素失败。测试将HDMI输入RGB与两级流水线前的坐标比较；改为同时观察桥输入DE/RGB及匹配坐标，保留整帧307200像素逐点检查。对照日志保存在tests/results/stage3_pattern_baseline.log。

FIFO诊断入口原先同时要求SW3=0和同步SW3=1，导致测试等待超时；修为K4+SW4明确进入诊断、SW3选择FIFO变体。未按K4的普通电梯上电不进入诊断，固定电梯编译模式继续禁用该入口。

## 验证范围

`tb_emergency`验证忙时请求、PIC5晚到、故障前后告警、转场取消、原日常页与自动模式恢复、原页无效回退、解除取消及2/3帧边界；`tb_emergency_top`直接编译生产顶层，验证菜单/缩略图抢占恢复、焦点冻结、双沿抖动、双来源重叠及菜单切换。边界PLL/SDRAM采用模型；该测试不表示实板验收。

物理时序、完整回归、独立快照与BIT对应关系以修复验证/stage3中的最终收集结果为准。实板显示质量、外部屏幕实际亮屏、按键手感仍待验收。

最终物理结果：SWNS +0.562ns，HWNS +0.026ns，两个TNS为0，LUT16834/19600(85.89%)。时钟/PLL/无路径约束检查为0；4个既有dummy node及12个输入、31个输出缺板级delay继续公开记录，不声称I/O接口已经实测验收。BIT SHA256为`ab4912bb1a0c70f1d362cf97bc72b01232fd752b19d0c22458d216714b8429f1`。
