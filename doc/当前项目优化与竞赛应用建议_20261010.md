本文针对当前已经完成读卡提速、首图提前显示、SDRAM 突发/仲裁、照片优先界面、启动静音、缩略图居中和数码管顺序修正的版本，区分“构建报告已证明的事实”“根据 RTL 得出的瓶颈判断”和“需要实板测量的功耗结论”。

## 1. 当前架构与可量化基线

数据链路为：TF 卡 SPI → FAT32 扫描/文件流 → BMP24 解码 → 写入跨时钟 FIFO → SDRAM 帧缓存 → 突发读取/预取 → 亮度、对比度和转场 → 字幕、状态、参数、缩略图、音轨面板 → HDMI 视频与音频数据岛。控制链包含按键、UART 字幕、Flash 双槽配置和错误恢复。

当前时钟合同为系统 50 MHz、SDRAM 40 MHz、像素 25 MHz、HDMI 串行 125 MHz，视频为 640×480、总时序 800×525，刷新率约 59.524 Hz。单个 RGB888 像素在 SDRAM 中占 32 bit，显示读取理想吞吐约 73.14 MB/s；SDRAM 接口的理论上限为 160 MB/s，实际还要扣除刷新、行切换和突发间隙。

## 2. 主要瓶颈

### 2.1 像素域组合路径过长

`src/user_source/rtl/promax_audio_waveform.v` 在一个像素周期内同时完成面板判定、采样索引、双口采样 RAM 选择、静音移位、插值、波形/辉光/填充/网格/峰值柱判定和透明混合。当前最差路径正是音轨输出级，逻辑 29 级、布线占路径延迟 69%。

`src/user_source/rtl/promax_text_overlay.v` 还包含字符区域判定、常数除法和字形地址计算；字幕、状态、参数、计时和波形层串联后，最终选择器和高扇出控制信号进一步增大布线压力。

### 2.2 存储与 FAT32 控制逻辑占用大

综合层级显示 `u_storage` 约 3953 LUT、5 DSP、6 BRAM；其中 `u_volume_scanner` 约 1360 LUT，`u_bmp_decoder` 约 887 LUT，`u_file_streamer` 约 560 LUT。`fat32_file_streamer.v` 在簇切换时仍使用 `(cluster_value - 2) * sectors_per_cluster`，应优先改为移位或低频事件计算，而非每次地址变化都保留宽乘法。

### 2.3 配置、字幕和数码管有低速重复计算

`config_journal.v` 的 `crc16_chunk40` 在组合函数中展开 40 次 CRC 迭代，加载两个槽位和保存时重复使用；`subtitle_uart_controller.v` 用宽行缓存再集中解析。顶层周期毫秒转秒逻辑在 `seconds_busy=0` 时会反复启动，即使周期没有改变；`seg7_panel.v` 仍可在参数更新事件中预计算 BCD。

这些任务的业务频率远低于像素时钟，持续组合翻转没有带来用户可见收益。

### 2.4 乘法和无效区域仍会翻转

亮度/对比度模块每通道包含乘法；视频转场也有 RGB 乘法。即使 alpha 或增益处于端点，若输入一直变化，乘法器内部仍可能翻转。消隐区约占总像素时序的 26.86%，可以通过 DE 使能和操作数隔离减少活动，但不能停止 HDMI 时序本身。

音量已经实现上电/K1 复位默认 0；音频链仍须在静音时停止未选音源和增益输入的无效变化，同时继续输出合法的 HDMI 静音音频包。

### 2.5 当前低功耗接口存在边界

`hdl_source/SD/sdram.v` 的原语 `.cke(1'b1)` 固定为高，当前 `self_refresh_open` 只是刷新请求，不能宣称已经支持运行时自刷新。`sys_pll_promax_40.v` 使用 `STDBY_ENABLE("DISABLE")`、`.stdby(1'b0)`，不能用普通逻辑与时钟相与来门控时钟。SD、Flash、SDRAM 和 HDMI 在持续播放时仍有必须的协议活动，功耗百分比必须由实板测量确认。

## 3. 优化方案、收益、难度与取舍

| 优先级 | 措施 | 实现要点 | 预期收益 | 难度 / 取舍 |
| --- | --- | --- | --- | --- |
| P0 | 音轨流水线拆分 | 将区域判定、采样/几何、颜色混合拆为 2～3 级；同步 RGB、HS、VS、DE、坐标和音频岛 | 缩短 29 级路径，争取建立裕量达到工程目标 1 ns 以上 | 中高；增加 1～3 像素延迟和寄存器翻转，需逐像素与 HDMI 回归 |
| P0 | 复位同步释放与扇出分摊 | 各时钟域异步断言、同步释放；用 ready/ack 控制 FIFO 和预取重装 | 改善恢复路径和冷启动可靠性，避免用 false path 掩盖问题 | 中高；增加数拍启动延迟，需覆盖首帧、切图和 PLL 重锁 |
| P1 | 参数变化事件触发 | 周期转秒、OSD 十进制、数码管 BCD 仅在 dirty 或复位时计算，帧边界提交 | 稳定显示时停止大量低速组合翻转，减少 LUT 和功耗 | 低；参数更新延迟可接受，需处理连续按键更新 |
| P1 | 按参数上界缩窄计数器 | UART 位周期约 9 bit、307200 像素约 19 bit、65535 超时约 16 bit；文件 LBA 保留 32 bit | 缩短比较/加法器和寄存器，降低扇出 | 低中；工具可能已经裁剪部分位，需保留溢出检测 |
| P1 | 字符 ROM 与扫描计数 | 用 cell/column 计数替代 `/12`、`/18`，将字符行位图放入小 ROM；参数字符先缓存 | 减少常数除法、动态切片和高扇出，BRAM 余量足 | 中；ROM 读延迟需和 OSD 流水一致 |
| P1 | 顺序 CRC、流式 UART | 一个 16 bit CRC 状态机复用两个槽位；UART 按字节维护合法性，回车提交 | 低速任务只在请求期间翻转，节省组合逻辑 | 中；每 40 bit 约 1.6 µs，远小于 Flash 擦写时间，格式必须兼容 |
| P1 | DE/端点操作数隔离 | 仅在有效像素更新 RGB 算术输入；alpha=0/255、音量=0 时旁路并保持乘法输入 | 降低消隐区和静态画面活动率，保留现有显示效果 | 中；不能停止 TMDS、音频 ACR 和同步信号 |
| P1 | FAT32 地址低频计算 | 在簇切换事件中计算 `sector_lba`；若 `sectors_per_cluster` 为 2 的幂使用移位 | 减少宽乘法和高扇出，缩短文件流路径 | 低中；需覆盖非 2 的幂簇大小和碎片文件 |
| P2 | 音源按需运行 | 未选合成音/PCM 停止样本发生器；静音时保持 FIFO 合法排空 | 降低音频源与增益网络活动，减少无效翻转 | 中；要定义切换相位和淡入，避免爆音 |
| P2 | 共享 1 ms CE | 按键去抖、长按、轮播等使用共享使能；音频采样仍保留 48 kHz 节拍 | 减少重复长计数器和比较逻辑 | 中；需验证计时误差和同时事件 |
| P2 | SD 空闲停机与缩略图跳读 | 首图/缩略图完成后停止 SD 状态机；缩略图黑区不读 SDRAM，仅窗口内取图 | 降低空闲串行活动；缩略图模式理论上可减少约 75% 读像素 | 中高；读端、突发边界和缓存标志需一起修改 |
| P2 | 真实 PCM/WAV 音画绑定 | 按图片编号绑定音乐或语音，切图事件触发音频段，波形与播放同步 | 提升比赛展示辨识度，体现多源融合 | 中；需要素材版权记录、SD 带宽和播放异常恢复 |
| P2 | 8/16 频带低资源频谱 | 低速控制域采用 Goertzel 或共享 MAC，不上大型 FFT；按帧更新柱状图 | 比纯波形更直观，增强音频可视化 | 中高；DSP 已用 17/29，需做资源预算和时延评估 |
| P3 | Flash 深度掉电 | 确认器件型号和 FPGA 配置依赖后，空闲发送 B9，访问前 AB 唤醒 | 降低长时间配置 Flash 待机电流 | 中；必须验证热复位、掉电恢复和 SPI 所有权 |
| P3 | SDRAM/PLL 深度待机 | 只有厂商原语暴露 CKE/self-refresh、PLL standby 时才做；定义进入、保持、唤醒状态机 | 可能显著降低待机功耗 | 高；画面会暂停或黑屏，唤醒要重新锁定并预填 FIFO |
| P3 | 板级负载开关 | 仅在原理图确认可控电源、反向供电和上电时序后关闭 TF/显示外设 | 外设真正断电，适合长时待机 | 高；需要硬件配合，不能把 FPGA 内部逻辑当作独立电源域 |

### 3.1 推荐首轮实施顺序

1. 先做音轨流水线、复位同步释放，并逐项完成综合、STA、CDC、图像逐像素和 HDMI 音频回归。
2. 再做参数事件触发、计数器定宽、字符 ROM、顺序 CRC、DE/端点隔离。这些改动风险低，适合建立资源和活动率对比基线。
3. 根据实测启动时间选择 SD 连续读、双缓冲和簇地址优化。提高 SPI 频率可能缩短时间，但会提高瞬时功耗，应同时比较“加载能量”而不只比较峰值电流。
4. 最后再评估真实 PCM、频谱、Flash deep power down 和 SDRAM/PLL 待机。任何深度待机方案都必须先确认板级原理图和安路器件手册。

## 4. 启动黑屏约 5 秒的专项建议

首图提前显示和后台加载已经写入当前版本，但仍需在实板上分段打点确认 5 秒来自哪里：上电等待、SD 初始化、FAT32 扫描、首个 BMP 定位、BMP 解码、SDRAM 排空还是 HDMI 首帧锁定。建议在 50 MHz 域增加 8 个事件时间戳，并通过现有 UART 输出：`power_ready`、`sd_ready`、`volume_ready`、`first_file`、`first_bmp_header`、`first_frame_written`、`first_frame_displayed`、`background_done`。

优化目标按阶段设定：先保证首图显示时间稳定，再缩短后台完成时间。不要在首图可显示前等待全部 4 张图片和缩略图；不要用提高时钟或放宽约束掩盖 SD 卡响应、FAT 碎片和 FIFO 背压问题。

## 5. 低功耗测量与验收方法

功耗结论目前只能写成方向性预期，必须在相同电压、温度、TF 卡、照片、音量和显示器条件下实测。至少记录：启动平均/峰值电流、正常播放功耗、静音功耗、无按键空闲功耗、保持画面功耗、黑屏待机功耗和唤醒时间。

活动率验证使用真实 640×480 时序、代表性照片和音频生成 VCD/SAIF；若工具支持，使用布局布线后的电容和毛刺估计。依据 `P_dynamic ≈ α·C·V²·f`：逻辑简化主要降低 C，CE/操作数隔离降低 α，降频降低 f，真正的外设断电或器件低功耗模式才会显著降低静态和待机部分。少用 LUT 不能直接等价为整机省电。

验收还应覆盖：空白 Flash、保存音量 255、配置损坏、Flash 异常、拔卡、坏 BMP、碎片化 FAT、FIFO 空满、连续切图、长时间自动轮播、复位发生在不同相位和至少 2 小时连续运行。

## 6. 官方比赛通知要点

依据官方通知 PDF《全国大学生嵌入式芯片与系统设计竞赛 2026 选题指南模板》（第 14～15 页），赛题一为“基于安路 EG4S20 的 HDMI 多媒体播放系统”。要求使用安路 EG4 系列 FPGA，以音视频融合为方向，自主完成控制逻辑和数据处理，体现并行处理、实时控制、低延迟显示、音画同步和多源信息融合。可使用 TF/SD 资源扫描、BMP 解析、SDRAM 帧缓存、HDMI 音视频、交互控制和音视频联动；不得使用额外处理器替代 FPGA 控制或算法。

官方列出的扩展方向包括：动态时间戳和多图层字幕、淡入淡出/滑动转场、不同分辨率缩放适配、亮度/对比度等实时参数叠加、音频波形或频谱可视化。通知说明扩展项按数量、技术难度、完成质量、稳定性和现场效果综合评价，不是简单“堆功能”。第 35 页强调作品原创、版权不能已转移，使用开源内容要保留版权声明并注明来源。

当前工程已覆盖大部分基础项和多项扩展项。答辩材料仍应补充实测启动时间、图片切换延迟、音画同步误差、资源/时序、功耗、长时间稳定性和异常恢复证据。

## 7. 推荐产品定位与功能增强

推荐统一叙事为：**基于国产 FPGA 的低功耗音视频信息发布与交互终端**。演示时按“上电默认静音 → 首图快速出现 → 状态/参数显示 → 按键切图和自动轮播 → 真实音乐或语音 → 波形/频谱随音频变化 → 亮度/对比度调节 → 应急页/字幕 → 拔卡或坏图自动恢复”的顺序进行。

优先选择一个明确场景，而不是同时宣称多个产品：

1. **校园/实验室数字展陈**：照片、讲解音频、设备状态和编号联动，最容易准备原创素材和现场演示。
2. **博物馆/景区音画导览**：每张照片绑定语音讲解，字幕显示地点和时间，突出音画同步。
3. **应急信息发布牌**：按键触发高优先级图片和滚动字幕，拔卡/坏图时显示错误码并自动恢复，突出实时性和可靠性。
4. **低功耗户外宣传终端**：加入保持画面、定时唤醒和亮度策略，量化运行/待机能耗。

最有辨识度、且适合当前资源的三项增强是：真实 PCM 讲解音频与照片绑定、8～16 频带低资源频谱、应急优先页和故障恢复。复杂 FFT、双线性缩放、大容量素材管理和多 FPGA 暂不应作为首轮重点，因为当前 LUT 和 DSP 余量有限。
