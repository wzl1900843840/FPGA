## 模板说明

R=先核对现状；D=可实施任务；C=必须先闭合的口径。完整业务背景与设计分别见需求、开发计划，本文件只记录执行流程。

## 一、任务目标

交付一个能解析现有与拟定扩展协议、按2秒演示1～5层、告警置顶并支持人工ACK复核的上位机，以及与之对应的协议与验收材料。

## 二、不做什么

不控制真实电梯，不新增云平台/图像处理；不改FPGA时钟体系；不覆盖用户已有修改的BIT；本轮规划不占用COM18、不烧录、不执行告警。

## 三、当前实施状态

- 已核对：已有接收窗口/日志/去重/ACK查询；旧ELEV改写A、自动ACK默认开启、ACK写出即确认等缺口。
- 已交付：需求、实现前设计、任务；未开发新软件或扩展协议。
- 尚未解决：新UI、楼层调度、人工ACK状态机、三项协议扩展及其实板验收。

## 四、能力地图核对

当前无`.ai-governance/capability-map.md`；已通过实际代码核对能力，不新建平行串口引擎。

|能力|复用对象|处理|
|---|---|---|
|界面/串口|App、SerialWorker|分模块扩展，保留启动入口|
|协议/共享状态|Receiver及正则|类型化解析和状态仓库|
|后端Service/数据库|无|不新增|
|审计/异常|Journal、JSONL、CSV|补失败路径、TX日志和回放|
|测试|test_rescue_receiver.py、生产UART位流|延续并新增有价值的竞态/调度覆盖|
|协议文档|现有救援闭环说明|新增版本对照，不篡改历史结果|

## 六、D 类任务：可进入设计或开发准备

### D01 建立上位机回滚点与模块骨架（P0）

前置：R01。

- [ ] 记录HEAD、用户已有修改、候选BIT哈希；仅为本次文件建立独立检查点，保留现有修改。
- [ ] 将旧接收端整理为兼容入口+host_app包，保留Journal/假串口样例。
- [ ] 默认人工ACK在连接前生效，消除先连串口后应用设置的自动确认竞态。
- [ ] 明确状态事件/命令模型与工作线程唯一串口所有权。

通过：旧查询/接收/日志仍可用，既有测试适配通过；提交独立检查点。

### D02 解析、状态仓库与调度（P0）

前置：D01。

- [ ] 补ELEV、PIC/VOL/PRD/BRT/ERR与现有RESCUE/BOOT严格解析，保留原始字节。
- [ ] 区分活动事件快照、实时回读、演示目标、字段更新时间。
- [ ] 单普通事务、ACK优先、查询合并、500ms初始超时、6秒失联门限。
- [ ] 超时后暂停控制并用明确类型查询同步，不盲重试匿名OK控制。
- [ ] 记录完整RX/TX、会话、命令、响应和失败；关键告警日志失败仍显示但禁ACK。

通过：半包/粘包/超长/异步事件插队/迟到回复/落盘失败覆盖；提交检查点。

### D03 看板与人工告警闭环（P0）

前置：D02。

- [ ] 固定告警区、大号楼层、方向/门/通信/故障状态、事件表与串口页。
- [ ] 点击“收到响应”校验当前会话/ID/活动状态/落盘，发送ACK后查询复核。
- [ ] 区分ACK已发送/设备已接受/仍告警/已解除；不发送ALERT OFF作为ACK副作用。
- [ ] 重发只计数、恢复不同ID、迟到ACK、回卷、重连恢复与记录冲突正确处理。
- [ ] 断链保留告警、禁用控制；回放不会发送任何字节。

通过：从模拟与假串口到实际回包的生命周期一致；提交检查点。

### D04 2秒电梯演示与旧版兼容（P0）

前置：D03。

- [ ] 单调时钟往返1～5层、端点S、正常关门C；目标与回读分别展示。
- [ ] 实现开始/暂停/继续/停止、手动互斥，忙时顺延不积压。
- [ ] 旧版任何有效告警/状态未知期间禁ELEV写入；不复制合成A成为UART源A。
- [ ] 告警/断链/启动即暂停；解除只允许用户继续，不自动恢复。

通过：至少30次计划步进，无短时间补发；任意步进点告警不被清除；提交检查点。

### D05 三项最小协议扩展与固件门禁（P0）
