## 一、当前理解

开发一个本地Windows上位机，把FPGA上报的文本串口变成清晰的运行看板，并提供1～5层每2秒往返演示、告警置顶和人工接收确认。优先扩展已有Python/Tkinter接收端，不更换技术栈、不把媒体处理搬到电脑。

最重要的业务链：连接并回读 → 日常楼层演示 → FPGA告警主动上报 → 页面置顶并暂停演示 → 点击“收到响应” → 发送事件ACK → 查询设备确认 → 告警解除 → 手动继续。

## 二、复杂度判断

- 初判：中等，命中跨3个以上模块和嵌入式协议变更。
- 影响面：`tools/rescue_receiver.py`、新增上位机包与测试、UART命令解析/状态回报及顶层接线。
- 不申请降级；先设计再实现。用户已要求制定计划，并允许有意义地拓宽协议；本轮交付计划，不直接改固件。
- 当前候选LUT 18242/19600（93.07%），SWNS +0.221ns、HWNS +0.025ns，扩展必须控制资源并重新布局布线。

## 五、设计方案

### 5.1 推荐方案

#### A. 功能范围与优先级

|等级|功能|具体行为|
|---|---|---|
|P0|连接管理|枚举端口、显示设备描述、连接/断开；COM18优先推荐；115200 8N1固定；连接后逐条同步状态|
|P0|状态可视化|大字号已回读楼层、方向、门状态、有效告警、通信状态、错误码、数据新鲜度；未知值不能伪装正常|
|P0|2秒演示|开始/暂停/继续/停止；默认1→2→3→4→5→4→3→2→1；目标值与回读值分开|
|P0|人工确认|告警置顶，点击“收到响应”发送当前事件ACK；默认不自动ACK|
|P0|诊断与记录|RX/TX原文、解析结果、会话与事件时间线、导出CSV/JSONL；断链保留告警|
|P1|手动演示|选择楼层/方向/门；触发UART演示告警、解除UART演示告警；与自动楼层互斥|
|P1|启动看板|五个BOOT节点横向展示，标有效位、饱和与未知，明确内部首像素边界|
|P1|演示辅助|全屏、告警提示音静音、历史筛选、离线回放；测试页可关闭/延迟/自动确认|
|P2|交付|Windows独立程序及版本信息；资源允许时再做进一步诊断协议|

#### B. 模块划分

推荐入口保留`tools/rescue_receiver.py`，重构为轻量启动器，新增`tools/host_app/`：

|模块|职责|边界|
|---|---|---|
|`serial_transport.py`|唯一串口拥有者；读取、分行、完整写入、断开清理|工作线程不直接更新控件|
|`protocol.py`|RESCUE/状态查询/ELEV/BOOT/普通回报/新增协议编解码与字段验证|只解释数据，不修改UI，不自动触发控制|
|`scheduler.py`|完整行发送、优先级、普通命令单事务、超时/对照查询|不允许多个模块直接write串口|
|`device_state.py`|当前设备状态、字段来源/时间、会话及过期标记|运行状态与告警历史快照分别保存|
|`demo_controller.py`|单调时钟2秒步进、方向切换、暂停/继续|只产生楼层意图，不绕过调度器|
|`alarm_manager.py`|当前事件、重发去重、人工ACK、设备确认、恢复/失联|按钮动作不等于设备状态|
|`journal.py`|原始RX/TX、解析、持久化、CSV、轮转、回放|关键告警落盘完成后才开放确认|
|`ui.py`|ttk布局、Canvas电梯示意、告警区、事件表、专家页|主线程通过事件队列刷新；不sleep或执行阻塞I/O|
|`config.py`|端口、窗口、演示设置、声音开关|重启不自动恢复控制任务；不保存待发ACK|

主线程与I/O线程通过命令/事件队列通信；UI每50ms限量处理一批事件。状态刷新可合并，求援/解除/异常不能被普通状态合并丢弃。文件导出和回放读取在后台执行。

#### C. 界面布局

建议1280×800可缩放，窗口最小尺寸以控件不遮挡为准：

```text
┌ 梯间守望 · 设备演示与应急联动控制台 ─ 端口/连接/会话/数据时效 ┐
│ 固定告警区：事件ID、楼层、来源、持续时间、状态 [收到响应] [静音] │
├──────────────────────┬──────────────────────────┤
│ 1～5层电梯示意        │ 大号当前楼层 / 方向 / 门状态             │
│ 轿厢跟随设备回读值    │ 有效告警 / 确认状态 / 故障 / 模式         │
│ 未回读目标用虚线标注  │ [开始] [暂停] [继续] [停止] 2秒/步       │
│                      │ 手动楼层、方向、门；演示告警与解除       │
├──────────────────────┴──────────────────────────┤
│ 页签：事件时间线 | 原始串口 | 启动计时 | 历史/回放 | 专家测试   │
└ RX/TX统计、最后有效回包、日志路径、固件/协议版本、导出/全屏      ┘
```

- “置顶”默认指应用内固定在最上方，不随页签/表格滚走；可选窗口始终置顶，不强制抢焦点。
- A=1未确认用红底/图标/文字，可低频柔和强调；已确认但未解除仍保留醒目标识。颜色必须辅以文字，不只靠闪烁。
- “收到响应”按钮名保留用户要求，提示文字解释为“接收端已记录并确认本次求援”。没有有效当前ID、记录失败、历史/回放、断链时禁用。
- 故障提示与求援告警分层：红色求援最高、橙色系统故障/断链其次、普通状态最后。媒体故障不自动伪造求援事件。
- 手动发送页面标“仅演示状态输入”；电脑不承担真实电梯运动控制。

#### D. 数据交互与现有协议

115200、8N1、无流控，发送ASCII+CRLF。FPGA输入行上限40字节（不含结束符），PC接收按完整CRLF行组包，最多512字节；超长丢弃至下一个换行并记录。保留原始字节，已知ASCII消息严格解析；未知字节转义展示，不能替换字符后当合法消息。

|现有消息/命令|用途及处理|
|---|---|
|`ELEV=F05,D=U,DO=C,A=0`|楼层05/上行/关门，同时改写UART告警；当前返回OK。F为两位十进制，地下FB1～FB9；D=U/D/S，DO=O/C/M（M按未知显示）|
|`ELEV?` → `ELEV=F05,D=U,DO=C,A=1`|读取已应用系统域楼层及合成告警；系统未获得楼层时不根据数字默认值宣称实际在0层|
|`ALERT=ON` / `ALERT=OFF`|设置/清除UART告警；不清本地SW4；普通回执OK|
|`RESCUE,ID=0001,A=1,F=05,D=U,DO=C,S=L,E=00`|主动求援快照；S=U/L/B；楼层还可为--；ID/E为十六进制|
|`ACK=0001`|仅当前有效事件匹配才生效；旧版静默，不等待OK|
|`RESCUE?` → `RESCUE,ID=0001,A=1,C=ACKED`|查询有效告警与通信状态，C=IDLE/WAIT/ACKED/TIMEOUT|
|`BOOT?` → `BOOT,SD=0065,SC=00DC,P1=033E,TF=0352,P5=05DC,V=1F`|十六进制毫秒；按V位判断是否发生；FFFF饱和；不是显示器点亮时间|
|`MEDIA PLAYER READY`|启动标志，新建会话并停止未完成控制|
|`PIC 1 A`、`VOL FF`、`PRD 01388ms`、`BRT 80`|变化事件；解析十六进制数值；PRD五位十六进制毫秒|
|`ERR 87` / `ERR` / `ERR ELEV`|分别是系统故障事件、普通命令错误、电梯命令错误；先精确分类，避免混淆|

串口协议没有CRC，结构验证不是CRC校验。未知故障码显示原码及“未映射”；不能编造故障原因。报文示例均为协议示例，不是实测记录。

**发送调度：**ACK优先于未发送普通控制，普通控制优先于轮询和调试；已写出的完整命令不撤回、不插字节。一次仅一个普通命令等待响应，异步RESCUE/PIC/ERR不能误当普通回执。ACK是固件允许的特例，可在等待普通回包时插入下一条完整输入行，不占普通响应槽。确认查询仍要等待已有普通事务结束。

**连接同步：**先建立会话并禁止自动ACK，再逐条`RESCUE?`、`ELEV?`；扩展探测`INFO?`，未知命令ERR则进入旧版兼容。一次超时不直接判旧版，先提示未响应；BOOT?按需查询。每个普通请求建议500ms初始超时，可配置；超时暂停演示，使用类型明确的状态查询恢复同步，不盲目连续重发依赖匿名OK的控制。

**轮询：**旧版每2秒低优先级查询ELEV?；存在告警时每1秒查询RESCUE?，ACK发送后安排一次优先确认查询；新版正常每2秒STAT?，告警时每1秒。请求合并，最多各保留一个待查询，不堆积；3次连续未响应或距有效查询回包超过6秒标为通信异常。普通未知文本和回显不能把链路刷新为正常。

#### E. 有意义的协议扩展（拟定v1.1）

先保留旧命令及43字节RESCUE格式；不增加JSON或通用长字符串解析。三项首选扩展如下：

|优先级|新命令/通知|拟定返回示例|价值|
|---|---|---|---|
|P0|`INFO?`|`INFO,P=11,FW=0001,HW=EG4S20,CAP=0007`|识别协议/固件/器件与能力，不靠超时猜功能|
|P0|`FLOOR=F05,D=U,DO=C`|`OK`；参数非法`ERR FLOOR`|只更新楼层/方向/门；**绝不改写UART告警**，消除演示清告警隐患|
|P0|`STAT?`|`STAT,F=05,D=U,DO=C,A=1,S=L,C=WAIT,I=0001,E=00,M=1F`|一次取得系统域运行状态、当前来源、确认状态、编号、系统故障及图片就绪位|
|P1可选|`COMM,ID=0001,A=1,C=ACKED`|设备主动通知，不要求PC回复|状态变成WAIT/ACKED/TIMEOUT/IDLE时通知，减少确认等待；仍可查询补偿丢失|

`INFO`中P=11表示拟定1.1，FW是发布固件编号（示例0001，不是当前Git哈希或已下载版本）。CAP为16位十六进制：bit0=FLOOR，bit1=STAT，bit2=INFO；bit3=可选COMM；其它位保留为0。只有CAP声明的扩展才启用。`INFO?`不存在或ERR时保留全部旧版能力。

`STAT`字段约定：F仍为两位楼层/B1～B9，未获得有效楼层为--；A是合成告警；S=U/L/B/N，N无当前来源；C沿用四态；I沿用最近有效求援ID（不是恢复消息ID）；E为当前系统域故障码；M为PIC1～PIC5已校验并写入排空的5位掩码（十六进制）。A=0时S=N，恢复历史来源从RESCUE恢复快照读取。全部字段在接受查询时整体锁存。

`STAT`不伪装报告像素域实际页号、五态控制器当前状态或显示器连接：这些信号需要专门CDC回传与帧快照，作为后续可选`VIEW?`调查，不塞入首版。M不是实时卡在位检测，E也不能覆盖未接入的像素域错误。UI标“系统回报”，不标“全部硬件健康”。

首版扩展请求均小于40字节，拟定回复控制在63字节以内；保留MAX_LINE=40，回复种类至少扩至5位并审计所有比较和译码，不盲目放大行缓存。新增命令复用固定格式解析、现有UART TX和系统域信号；新快照不能直接读取未同步像素域信号。

**暂缓的扩展：**UPTIME/温度/电流/电梯人数没有现成可信数据，不添加假遥测；PING独立心跳与STAT功能重复，首版不加；额外ACK回执由RESCUE?/STAT?满足，不重复造确认机制；CRC/命令序号可作为后续协议v2单独设计，不能局部添加后宣称旧帧也有完整性保护。

#### F. 楼层演示状态机

状态：STOPPED、RUNNING、PAUSED_USER、PAUSED_ALARM、PAUSED_LINK。连接和初始状态同步完成后才能开始。

1. 开始时设置目标1层、端点停止S、关门C；发送后等待回执，再查询已应用状态。确认后主卡显示1层。
2. 以后每2秒产生一次新目标：2U、3U、4U、5S、4D、3D、2D、1S，循环。2秒为模拟步进，不承诺真实轿厢速度；Canvas只表现示意。
3. 使用单调时钟的下一截止时间；事务忙/ACK抢占时跳过已过截止点，下一次从新的完整2秒周期开始，不连续补发追赶。
4. 告警/链路异常/设备重启马上暂停并删除未发楼层命令，已发事务允许收尾。旧版告警期间禁止ELEV写入；新版FLOOR不改A，但默认也暂停。
5. 用户暂停或停止时，若连接正常、状态可靠且无告警，发送同层D=S；旧版不为停止而发送A=0覆盖有效告警。停止不清告警，不重置设备楼层到1。
6. 解除后停留暂停，用户继续时从已回读楼层恢复；若楼层不在1～5或未知，要求重新开始演示，不猜测下一层。
7. 手动模式与自动模式互斥；手动发送同样通过调度器，并显示发送/回执/回读结果。

#### G. 告警处理与ACK闭环

业务活动状态和通信状态是两个轴：A=1即告警仍有效；C=ACKED仅表示确认被设备接受。

|事件|界面与调度动作|发送行为|
|---|---|---|
|新A=1求援|立即置顶并暂停；保存ID、首次楼层/来源/故障快照；持久化|默认不自动ACK|
|同活动ID同内容重发|增加重发/接收计数和末次时间，保留首次快照，不重复建记录|人工尚未确认不发送；已点击确认且仍为当前事件时可幂等重发ACK|
|同ID内容冲突|记录异常、置通信警示，禁止基于冲突报文自动确认|优先查询当前状态|
|点击“收到响应”|先复核会话/ID/当前A=1/落盘成功；显示确认中|`ACK=ID`，之后RESCUE?或STAT?复核|
|ACK完整写出|显示“ACK已发送，待设备确认”|不等待旧版静默ACK的OK|
|同ID、A=1、C=ACKED|显示“设备已接受接收确认”，保留告警区|不发送解除命令|
|C=WAIT/TIMEOUT|显示待确认/设备确认超时；迟到的有效ACK仍可接受|用户可点击确认/重试，查询核实|
|A=0恢复事件或有效状态查询A=0|结束当前事件，取消未发ACK，保留历史，演示仍暂停|无恢复ACK；用户自行决定继续|
|断链/启动标志|保留“未核实解除”的告警及旧历史；当前控制失效|清理旧任务，不重放旧ACK/楼层|

当前固件首次完整发送后1秒等ACK，最多重发2次；第三次后再等1秒进入TIMEOUT。人工操作可能晚于该窗口，UI不得自动用主机3秒计时判设备已超时，仍查询真实C。通信超时不等于乘客已脱险或告警解除。

恢复报文通常是新事件号，例如A=1 ID0001后A=0 ID0002；按同会话当前告警生命周期关联。内部记录键使用会话+本地事件代次+ID，重发去重只针对当前活动事件；处理16位ID回卷，不能把同ID永久视为旧事件。

重连时先RESCUE?恢复有效ID和C，再ELEV?/STAT?取得现状。如果没有原始求援快照，标“重连恢复的活动告警”，当前楼层不冒充首次求援楼层。首次事件内容经记录后才能人工ACK。启动标志/重连可切会话；旧固件无可靠持久启动序号，未观察到的静默复位无法仅靠ID完全识别，必须保留这一边界。

落盘失败：即刻显示磁盘/记录失败，仍显示已解析告警但禁用ACK；不伪装“已记录”。ACK写出后日志失败则提示“发送结果已发生、记录失败”，停止自动后续发送并查询核对，不能回写为未发送。

#### H. 合理扩展与交付

- 事件时间线：首次到达、各次重发、人工点击、ACK写出、设备确认、解除、断链分别记录；显示主机观测耗时，不冒充设备端测量。
- 故障码词典：只映射源码/文档中已验证的码，未知码保留十六进制；与命令ERR分开。
- 启动图表：BOOT有效位和五节点，缺失/饱和醒目；不输出未经实测的“首屏提速百分比”。
- 离线回放：读JSONL演示历史，页面固定“回放”标识，发送全部禁用；可用于排练，不能计为实板验收。
- 专家页：自动ACK、延迟ACK、关闭ACK、错误编号测试必须显式开启；回到正常模式恢复人工默认。
- 可选ASCII字幕输入最多12字符，遵循既有SUB能力；任意中文下发不在首版范围。
- 交付包括源码、依赖、启动入口、协议v1/v1.1对照、样例日志、截图、测试报告；发布固件另附源码/时序/BIT哈希。

### 5.2 不采用的方案

|方案|原因|
|---|---|
|重写为Web/Electron或换Qt|当前已有Tk/pyserial基础，新增运行环境与迁移成本；首版采用ttk+Canvas足够展示|
|多个线程直接发串口|会发生命令交错和普通回执错配|
|每2秒固定ELEV A=0|会解除UART告警|
|ACK后直接清红条/自动ALERT OFF|混淆接收确认与告警解除|
|大量周期遥测/任意JSON解析|当前FPGA资源与时序余量小，新增成本缺乏必要性|

### 5.3 复用与新增边界

复用pyserial、Tk/ttk、JSONL先记录后确认、现有协议样例及测试。扩展解析、调度、会话与UI；新增楼层演示和人工ACK生命周期。FPGA只做三项首选协议增量，COMM可选，不重构媒体/时钟/SDRAM架构。

## 七、风险

1. 资源占用93.07%、时序余量小：每项RTL增量独立回归/综合；打包超限或时序不闭合则退回该项，不放松约束。上位机旧版兼容功能可以独立交付。
2. 匿名OK无事务编号：普通单请求串行，超时后停止控制并同步查询，不承诺严格关联任意迟到回包。
3. 系统域查询不等于屏幕状态：字段标注来源，像素域CDC遥测另行实现验证。
4. 确认/解除竞态及断链：会话和事件代次校验在工作线程发送前再做一次；新ID/恢复/断开取消旧任务。
5. 设备固件不明：INFO能力握手+旧版模式；当前板卡烧录完成与版本尚未被本计划确认。
